# 基础
计算机系统的层次结构：裸机->操作系统->应用程序->用户
**操作系统**(Operating System, OS)：是指控制和**管理**整个计算机系统的**硬件和软件**资源，并合理地组织调度计算机的工作和资源的分配；以**提供给用户和其他软件方便的接口和环境**；它是计算机系统中最基本的**系统软件**
***程序在执行之前需要先读入内存***
操作系统的功能和目标——向上层**提供方便易用的服务**；将功能封装成服务，是用户可以更方便的使用
**GUI**(Graphical User Interface),**图形化用户接口**：使用户可以在形象的图形界面操作，无需记忆繁琐的命令
**联机命令接口**(又称**交互式**命令接口)：就是Win下的CMD
**脱机命令接口**(又称**批处理**命令接口)：一次性提出多条命令请求，交给操作系统处理
程序接口：可以在程序中进行**系统调用**(广义指令)来使用程序接口。普通用户只能通过程序代码**间接**使用
没有任何软件支持的计算机称为**裸机**，覆盖了软件的机器称为**扩充机器**，又称为**虚拟机**
操作系统的实现**对硬件机器的拓展**
操作系统是**资源的管理者**

## 特征
操作系统的特征：**并发、共享、虚拟、异步**
并发和共享式最基本的特征，二者互为存在条件

### 并发
**并发**：指两个或多个事件在同一时间间隔内发生。这些事情**宏观上是同时发生**的，**微观上是交替发生**的
**并行**：两个或多个事件同一时刻内发生，容易记混

操作系统伴随着“多道程序技术”而出现的。因此，**操作系统和程序并发是一起诞生的**
**单核CPU**同一时刻只能执行**一个程序**，各个程序只能**并发**地执行
**多核CPU**同一时刻可以执行**多个程序**，多个程序**并行**执行

### 共享
即**资源共享**，指系统中的资源可供内存中多个并发执行的进程共同使用
共享方式分为：**互斥共享方式**和**同时共享方式**；同样体现着并发和并行的思想
**并发性**：计算机系统中同时存在多个运行着的程序
**共享性**：系统中的资源可供内存中多个并发执行的进程共同使用

### 虚拟
指把一个**物理上的实体变为若干个逻辑上的对应物**。物理实体(前者)是实际存在的，逻辑实体是用户感受到的。
eg：程序**需要放入内存并分配CPU**才可运行。**空分复用技术**用户运行的程序大于当前实际内存容量。单核多进程所采用的是“**时分复用技术**”。
**空分复用技术**和**时分复用技术**和并发性是密切相关的，前者是虚拟存储器技术的基础，后者是虚拟处理器的基础

### 异步
在多道程序环境下，允许多个程序并发执行，由于资源有限，进程的执行**不是一贯到底**的，程序会冻结和恢复，这就是进程的异步性。
***只有拥有并发性，才有可能导致异步性***

## 发展与分类
**手工操作系统阶段**：将代码使用纸带机的方式输入计算机，计算机运行完毕后再以纸带输出
缺点：用户**独占全机**、**人机速度矛盾**导致资源利用率极低。

**批处理系统阶段**：单道批处理系统，引用脱机输入/输出技术(用外围机+磁带完成)，并由**监督程序**负责控制作业的输入、输出。外围机可以将程序提前存入磁带中。
缺点：**内存中仅有一道程序运行**，只有结束后才能调入下一道程序。**CPU有大量空闲时间等待I/O完成**，资源利用率低。

**多道批处理系统阶段**：当计算机运算完成时，下一道程序接着读入。多道程序**并发**执行，**共享**计算机资源。**资源利用率大幅提升**，CPU和其他资源保持“忙碌”状态，系统吞吐量增大。
主要缺点：用户响应时间长，**没有人机交互功能**（无法中途调试程序或输入参数，只能等待程序运行完成）

**分时操作系统阶段**：计算机以**时间片**为单位**轮流为各个用户/作业服务**，各个用户可通过终端与计算机进行交互。**解决了人机交互问题**，允许多个用户同时使用一台计算机，操作请求相互独立，感受不到其他用户存在。
缺点：**不能优先处理紧急任务**，对所有用户/作业都是完全公平的，循环的提供服务一个时间片，不区分紧急性

**实时操作系统阶段**：能够优先响应一些紧急任务，不需要时间片排队。具有**及时性**和**可靠性**
**硬实时系统**：必须在严格的时限内处理完事件
**软实时系统**：能够接受偶尔的超时

#### 其他的操作系统
网络操作系统是伴随着计网的发展而诞生的，能把网络中的计算机有机结合起来，实现数据传输等功能，**也实现了网络中各种资源共享（例如文件夹）和各台计算机之间的通信。**（例如Win NT就是典型的网络操作系统，网站服务器可以使用）
分布式操作系统：主要特点是**分布性和并行性**。系统中各台计算机地位相同，**任何工作都可以分布在这些计算机上，由它们并行、协同完成这个任务**
个人计算机操作系统：如Windows XP、MacOS，方便个人使用

## 操作系统的运行机制
程序的运行：代码->机器指令，**编译器**需要**翻译**给CPU
***指令***是处理器(CPU)能识别、执行的最基本命令；CMD作为交互式命令串口，和指令是有区别的，指令是**二进制机器语言**
用户运行的是**应用程序**，操作系统运行的是“**内核程序**”；内核程序组成了“**操作系统内核**”，也可以简称为“**内核(Kernel)**”;**内核**是操作系统最重要的核心部分，也是**最接近硬件的部分**，甚至一个操作系统只需要内核就够了(Docker仅需linux内核)
操作系统内核作为“管理员”，有时会令CPU执行一些“**特权指令**”，如：内存清零。这些指令影响重大，仅允许“**管理员**”——即操作系统内核使用

**CPU设计和生产的过程就划分了特权指令和非特权指令**，所以执行前就能判断指令的类型

#### CPU的状态
CPU有两种状态：**内核态**与**用户态**
处于内核态时，说明此时正在运行的是内核程序，可以执行特权指令
处于用户态时，说明此时正在运行的是应用程序，此时只能执行非特权指令

CPU中有一个寄存器叫**程序状态字寄存器(PSW)**，其中含有一个表示CPU状态的二进制位，1表示“内核态”，0为“用户态”
***别名***：内核态=核心态=**管态**；用户态=**目态**

**内核态->用户态**：执行特权指令——修改**PSW**的标志位为“用户态”，这个动作意味着操作系统主动让出CPU使用权
**用户态->内核态**：由“**中断**”引发，**硬件自动完成状态转换过程**，触发中断信号意味着操作系统强行夺回CPU的使用权

刚开机时CPU为内核态，内核程序运行完，由用户启动应用程序时让出CPU，当读取到特权指令时引发**中断信号**并夺回CPU控制权

## 中断与异常
***内中断也被称作异常***，外中断是**狭义**的中断
CPU上运行着**操作系统内核程序**和**应用程序**
在合适的情况下，操作系统会将CPU使用权转让，**中断**是让操作系统内核夺回CPU使用权的唯一途径。
如果没有中断机制，也就没有并发操作，不中断则会使一个程序一直运行下去
**内中断**：与当前执行的指令有关，中断信号来自于CPU内部，***若当前执行的指令时非法的，则会引发一个中断信号***。有时应用程序想请求系统内核的服务，此时会执行**特殊指令——陷入指令**，该指令会触发一个内部中断信号。
***陷入指令不是特权指令***，只是意味着程序主动将CPU使用权交给内核
内中断有：陷阱/陷入(trap)，故障(fault)，终止三种状态(abort)。故障由错误条件引起，是可以修复的，修复完成后内核将CPU使用权让给应用程序；终止是致命错误，无法修复，此时会直接终止该程序

**外中断**：与当前执行的指令**无关**，中断信号来源于CPU**外部**，时分复用技术就是外中断的延伸。
打印机通过**I/O**流发送**中断请求**，当输入输出任务完成时，向CPU发送中断信号

**CPU会根据中断信号的不同，采用不同的中断处理程序**。当CPU检测到中断信号后，会根据中断信号的类似查询“**中断向量表**”，一次查找相应的中断处理程序在内存中的存放位置。*中断处理程序一定是内核程序，需要运行在“内核态”*。

## 系统调用
操作系统作为用户和计算机硬件之间的接口，需要向上提供一些简单易用的服务。主要包括命令接口和程序接口。程序接口由一组**系统调用**组成
“系统调用”是操作系统提供给应用程序（程序猿/编程人猿）使用的接口，可以理解为一种可供应用程序调用的特殊函数，**应用程序可以通过系统调用来请求获得操作系统内核的服务**
![](系统调用.png)
例如通过库函数创建新文件，就肯定是需要操作系统提供的系统调用服务。
因为**部分资源需要互斥**的使用，所以需要操作系统对共享资源进行统一管理，并向上提供“系统调用”的服务，用户进程想要使用这些共享资源就需要**通过系统调用向操作系统内核发出请求**。内核会对请求进行协调处理。*先生，你也不希望你的打印机打印出别人的文档内容吧？*
系统调用(按功能分类)：***设备管理、文件管理、进程控制、进程通信、内存管理***
应用程序通过**系统调用**请求操作系统的服务。而系统中各种共享资源都由操作系统内核统一掌管，因此**凡是与共享资源有关的操作（如存储分配、I/O操作、文件管理等），都必须通过系统调用的方式向操作系统内核提出服务请求**，由操作系统内核代为完成。这样**可以保证系统的稳定性和安全性**，防止用户进行非法操作。**发出系统调用请求**是在**用户态**下完成的。
**别名**=陷入指令=trap指令=仿管指令

## 操作系统体系结构
操作系统层次中操作系统层可以分为**内核功能**(如GUI)和**非内核功能**(如时钟管理、中断处理)。
原语：具有原子性，不可被分割，必须一次性运行完毕。
内核是操作系统最核心的部分，Linux各个发行版所维护的就是非内核功能，用的都是Unix内核
大内核体系：进程管理，存储管理，设备管理，时钟管理，中断处理，原语等都是内核态
微内核体系：进程管理，存储管理，设备管理交由用户态，其他依旧是内核态
**CPU状态转换是有时间开销的**，会降低系统性能。大内核体系将操作系统主要功能都作为系统内核，运行在核心态，**高性能**，但是**内核代码庞大，结构混乱，难以维护**；微内核体系只把最基本的功能保留在内核，优点是**内核功能少，结构清晰方便维护**，缺点是**需要频繁进行CPU状态转换，性能低**
大内核/宏内核/单内核 操作系统：Linux、UNIX
微内核操作系统：Windows NT

## 操作系统的引导
操作系统引导(BOOT)
磁盘中操作系统所在盘称为**活动分区**，其中包含**PBR**和**根目录**
**主引导记录(MBR)**：包含了**磁盘引导程序**和**分区表**(在磁盘中，但不属于用户可直接访问分区)
**引导记录(PBR)**：负责找到**启动管理器**
主存中有**RAM**(随机存取存储器)和**ROM(只读存储器)**，**BIOS(基本输入输出系统)** 存放在ROM中，包含ROM引导程序，即自举程序；ROM中的数据不会随断电丢失，会指示CPU将MBR读入内存，然后CPU根据磁盘引导程序和分区表找到系统分区读入PBR与根目录，再进行操作系统初始化。
![boot引导](boot引导过程.png)
**操作系统初始化程序（即启动管理器）** 可在根目录下找到

## 虚拟机
传统计算机一台物理机只能运行一个操作系统，对于高性能机器可能会造成性能浪费，多个应用运行在同一个操作系统内可能会造成一些冲突，为了安全性考虑，所以产生了**虚拟机**
使用**虚拟化**技术，将一台物理机器虚拟化为多台虚拟机器(Virtual Machine, VM),每个虚拟机器都可以独立运行一个操作系统
同义术语：虚拟机管理程序/虚拟机监控程序/**V**irtual **M**achine **M**onitor/Hypervisor
第一类VMM直接运行在硬件上，每个虚拟机分配硬件资源，使用时间片占用CPU；只有虚拟机管理程序运行在**内核空间**中，使用内核态；当虚拟机想要使用内核指令时，指令会被虚拟机管理程序截获，交由系统内核处理
第二类VMM运行在**宿主操作系统**上，例如Virtual Box和VMware。虚拟机操作系统此时运行在用户空间中，不影响其他用户进程的运行。想要使用硬件资源时**向宿主操作系统(Host OS)发起请求**，然后再由虚拟机管理程序再分配。
![](VMM对比.png)
**特权指令**可以进一步进行级别划分，其中只有 **0 级（最高特权级）** 的特权指令由 **VMM（虚拟机监控器）** 直接执行，而较低特权级的特权指令则由 **Guest OS（虚拟机操作系统）** 在受控环境下执行或经由 VMM 进行拦截与处理，从而实现对硬件资源的安全隔离与有效管理。

# 进程
进程是程序的一次运行态，也可以说是程序的一个实例
程序是**静态的**，进程(Process)是**动态的**，是程序的单次执行过程
**PID**(Process ID)是每个进程**独一无二**的识别号
**UID**是表示进程所属用户，和PID一同出现，同时资源管理器中还会显示进程被分配的资源量(内存、I/O设备、占用的文件等)和进程运行状况(CPU使用时长，硬盘占用情况，流量消耗等)

这些信息都被保存在数据结构**PCB**(Process Control Block)中，即**进程控制块**
操作系统需要对各个并发运行的进程进行管理，**管理所需的信息都会被存放在PCB中**
PCB同时也是进程存在的唯一**标志**，进程被创建时，其所对应的PCB也会被创建，当进程结束时会回收PCB
***PCB中存放的是操作系统对进程管理工作所需的信息***

## 进程的组成
**进程实体**(**进程映像**)由**PCB**、**程序段**、**数据段**组成
PCB给操作系统，程序段和数据段是进程**自用**的
程序段存放的是可执行文件经过**编译后的程序代码（指令序列）**，数据段存放的是运行过程中产生的**各种数据（例如变量）**

**进程**是进程实体的**运行过程**，是系统进行**资源分配和调度**的一个独立单位。
***同一个可执行文件产生的多个进程程序段是相同的，PCB和数据段不同***

## 进程的特征
**动态性、并发性、独立性、异步性、结构性**
1. 动态性：进程是程序的一次执行过程，是动态的产生、变化和消亡的
2. 内存中有多个进程实体，各进程可并发执行
3. 进程是能独立运行、独立获得**资源**、独立接受**调度**的**基本单位**
4. 各进程按各自独立的、不可预知的速度向前推进，操作系统要提供“进程同步机制”来解决异步问题
5. 每个进程都会配置一个PCB。从结构上看，进程由程序段、数据段、PCB组成

## 进程的状态
***只要CPU处于空闲，就会挑一个就绪态的进程给予使用权***
三大**基本状态**：运行态、就绪态、阻塞态，这三种状态占据了大部分时间
进程**正在被创建**时，他的状态是“**创建态(New)**”，这个阶段操作系统会为进程分配资源和初始化PCB。
进程创建完成后进入“**就绪态/新建态(Ready)**”。处于就绪态的进程**已经具备运行条件**但是没有空闲CPU暂时不可运行。
**运行态(Running)**:占用CPU并在CPU上运行
进程运行时可能会请求**等待某个事件**的发生（例如等待资源分配或其他进程响应），此时操作系统会夺取CPU使用权限，并使进程进入“**阻塞态/等待态(Blocked/Waiting)**”，其他的**资源也会被剥夺**。即使CPU使用权未归还，当**等待结束后依然会进入就绪态**，并被重新分配资源。
一个进程可以执行exit系统调用，请求终止该进程。此时进程会进入“**终止态/结束态(Terminated)**”。操作系统会让该进程离开CPU并回收内存空间等资源，最后回收PCB。终止进程工作完成后，这个进程就消失了。

运行态->阻塞态是进程的**主动行为**
阻塞态->就绪态是**被动的**
**不能由阻塞态直接变为运行态，也不能由就绪态直接转换为阻塞态**

操作系统给进程分配的时间片到期时会使**运行态的程序进入就绪态**

## 进程的组织
PCB中会有一个变量state表示进程**当前状态**，用数字表示
操作系统会将**相同状态进程**组织起来
**链式**方式：执行，就绪状态各自一个队列。阻塞队列中每种阻塞原因都会新开一个队列，例如等待打印机、等待磁盘等。队列优先级高的进程会放置队头。

**索引**方式：给各种状态的进程建立索引表，表中存放进程的PCB地址，执行指针、就绪表指针、阻塞表指针会指向索引表中的PCB。

**在“链式方式 / 索引方式”组织进程时，通常只显式包含 _就绪、阻塞、运行（执行）_ 这三种基本状态。**  
其他状态一般要么被合并、要么不参与这种组织方式。
新建、终止、挂起等状态并非不存在，而是**在链式方式或索引方式组织进程时通常不被纳入考虑范围**。  
新建态（New）表示进程刚被创建，尚未进入就绪队列，一般不参与进程调度，且会在很短时间内转为就绪态，因此在进程组织结构中通常被教材忽略。  
终止态（Terminated/Exit）表示进程已执行结束，仅用于等待系统回收相关资源，不会再进入任何调度队列，对调度结构而言属于无关状态。  
挂起态（Suspend）多出现在支持虚拟内存或中级调度的系统中，其本质可细分为就绪挂起和阻塞挂起两类；在仅讨论基本进程状态及其队列组织方式时，挂起态通常不作展开，若涉及，教材一般会明确说明“在支持挂起的系统中”。

## 进程控制
对所有进程实施有效的管理，具有**创建**新进程、**撤销**已有进程、实现进程**状态转换**等功能
原语：**执行具有原子性**，不可被中断
状态转换就需要用到原语，如果没有原语，可能会导致进程完成状态转换后还未出队就已经收到了别的指令
正常情况下，CPU**每执行完一条指令都会检查是否有中断信号**，有则暂停程序，先运行中断处理程序；当CPU执行了**关中断指令**后，就会不检测中断信号，直到执行**开中断指令**，关开之间的指令就不会被中断，这样就实现了**原子性**
***开关中断指令是特权命令***
**创建原语**（创建进程时使用的原语）：申请空白PCB、为新进程分配资源、初始化PCB、将PCB插入就绪队列
引起进程创建的事件：用户登录、作业调度、提供服务、应用请求
用户登录：分时系统中，用户登录成功，系统会建立为其建立一个新的进程
作业调度：多道批处理系统中，有新的作业（外存中未投入运行的程序）放入内存时，会为其建立一个新的进程
提供服务：用户向操作系统提出某些请求时，会新建一个进程处理该请求
应用请求：由用户进程主动请求创建一个子进程

**撤销原语**（撤销一个进程）：从PCB集合中找到终止进程的PCB、若该进程正在运行，立即剥夺CPU并分配给其他进程、终止其所有子进程、将该进程拥有的资源还给父进程或操作系统、删除PCB
引起进程终止的事件：正常结束；异常结束；外界干预（例如任务管理器终止进程）

**阻塞原语**：找到要阻塞的进程对应的PCB、保护进程运行现场，将PCB状态信息设置为“阻塞态”，暂时停止进程运行、将PCB插入相应事件的等待队列
硬气进程阻塞的事件：需要等待分配某种资源、需要等待相互合作的其他进程完成工作
***唤醒原语和阻塞原语成对使用***
**唤醒原语**：在事件等待队列中找到PCB、将PCB从等待队列移除，设置进程为就绪态、将PCB插入就绪队列，等待被调度
引起进程唤醒的事件：等待的事件发生了

**切换原语**：将运行环境信息存入PCB中、PCB移入相应状态队列、选择另一个进程执行，并更新其PCB、根据PCB恢复新进程所需的运行环境
CPU中有很多**寄存器**用于存放程序运行时所需要的某些数据；**PSW**程序状态字寄存器；**PC**程序计数器，存放下一条指令地址；**IR**指令寄存器，存放当前指令地址；通用寄存器
引起进程切换的事件：当前进程时间片到、有更高优先级的进程到达、当前进程主动阻塞、当前进程终止
为了防止切换进程时通用寄存器中的数据被覆写后无法被前一个进程再合理的使用，所以会在PCB进程控制块中保存这些必要的寄存器信息，**当原来的进程再次投入运行时，可以通过PCB恢复它的运行环境**

## 进程通信
进程间通信(**IPC**, **I**nter-**P**rocess **C**ommunication)指2+进程之间的数据交互
进程间的通信需要**操作系统内核支持**
进程是分配系统资源的单位（包括内存地址空间），因此**各进程**拥有的**内存地址空间相互独立**；为了保证安全，**一个进程不能直接访问其他进程的内存地址空间**


### 共享存储
进程申请共享存储区域，可以通过这块区域进行数据交换；**是基于存储区**的共享，是一种**高级通信方式**；为避免出错（被随意覆写），各个进程对共享空间的**访问**应该是**互斥**的；数据的形式、存放位置都有**由通信进程控制**，而不是操作系统，这种共享方式**速度很快**
    - **基于数据结构的**共享：比如共享空间只能存放一个长度为10的数组。这种共享方式**速度慢**、**限制多**，是一种**低级通信方式**


### 消息传递
进程间的数据交换以**格式化的消息(message)** 为单位。进程间通过操作系统提供的“**发送消息/接收消息**”两个**原语**进行数据交换；分为**直接通信方式**和**间接通信方式**，消息在进程自身的内存空间中进行完善
    - 直接通信方式：消息由**消息头**和**消息体**组成，**消息头包括发送进程ID、接受进程ID、消息长度等格式化的信息**；由进程完成消息，然后进程的内存空间被复制到内核中，另一个进程使用接收原语指明要接收的消息来源程序。操作系统此时开始检查消息队列，当查找到指定的发送人时则会传递消息。需要**互相指明的通信方式**
    - 间接通信方式：通过“信箱”作为中间实体进行消息传递，向操作系统申请一片内存地址作为邮箱。**指明**发送原语所发送的**信箱**，接收者需要**指明从哪个信箱接收消息**，可以一（信箱）对多（进程）

### 管道通信
数据流动是**单向的**，一边写数据另一边读数据，**在内存中开辟了一块大小固定的内存缓冲区**，数据的两方都可以读写，但是不能同时读写，有队列的思想在，数据是**先进先出**的，不能和共享存储一样随意地读取共享区域中的数据。管道只能支持**半双工通信**，要**实现双向同时通信（全双工通信），则需要设置两个管道**
    - 各进程**互斥**的访问管道，由操作系统实现
    - 管道**写满时，写进程将堵塞**，直到读进程取走数据再唤醒
    - **读空时，读进程将堵塞**，直到写入数据再唤醒
    - 数据一旦读出就会彻底消失，所以***多个进程读同一个管道时可能会错乱***，对此：1. **一个进程允许多个写进程，一个读进程**(考试标准答案) 2.**允许有多个写进程，多个读进程，单系统会让各个读进程轮流从管道中读数据**(Linux的方案)
    - 未写满就可以写，未读空就可以读，这两个进程是可以同时运行的

## 进程同步
进程的**异步性**是指各并发执行的进程以各自独立的、不可预知的速度向前推进。
**同步**也称为**直接制约关系**，它是指为完成某种任务而建立的两个或多个进程，这些进程需要**协调**它们的**工作次序**而产生的制约关系（例如B等待A完成并传输数据）。进程间的直接制约关系就是源自于它们之间的相互合作。

## 进程互斥
进程的**并发**需要**共享**的资源。各个并发执行的进程不可避免的共享一些系统资源，例如内存，打印机，摄像头等I/O资源。
资源共享方式有**互斥共享方式**和**同时共享方式**
**一个时间段内只允许一个进程使用**的资源称为**临界资源**。许多物理设备都属于临界资源。此外还有许多变量、数据、内存缓冲区都属于临界资源。
临界资源的访问必须**互斥**的进行，又称作**间接制约关系**。**进程互斥**指当一个进程访问某临界资源时，另一个想要访问临界资源的进程必须等待。当前访问临界资源的进程访问结束，释放后，另一个进程才可访问临界资源。
代码体内可以由`进入区；临界区；退出区；剩余区`四个部分组成，进入区会检查是否可进入临界区，进入则会设置正在访问临界资源的标志，也可理解为是**上锁**
**临界区**也可称为**临界段**，是**访问临界资源**的代码段。
**进入区**和**退出区**是负责实现**互斥**的代码段，退出区负责解除正在访问临界区的标志，也称解锁。剩余区做收尾处理.

为了实现对临界资源的互斥访问，同时保证系统整体性能，需要遵循以下原则：
1. 空闲让进。空闲时允许一个请求进程立即进入临界区
2. 忙则等待。临界区内有进程时，其他进程等待进入
3. 有限等待。应该保证每个请求的进程不会无限等待（保证不饥饿）
4. 让权等待。进程不能进入临界区时，应该放弃处理机，防止进程忙等待。

### 单标志法
两个进程在**访问完临界区**后会把使用临界区的权限交给另一个进程，也就是**每个进程进入临界区的权限只能被另一个进程赋予**。`int turn = 0;while(turn != 1);`
**违反了空闲让进**的原则，因为自己退出临界区后无法连续进入，如果此时没有别的进程 需要进入临界区，则会饥饿

### 双标志先检查法
设置一个标志位Bool值数组flag[]，数组中各个元素用来**标记各进程想进入临界区的意愿***。每个进程进入前都先检查也没有别的程序想进，没有则把自身对应的flag[序号]设为true，之后开始访问临界区。
**可能会违反忙则等待原则**，进入区的检查和上锁并非是一气呵成的，所以可能会因为进程切换导致同时进入临界区

### 双标志后检查法
先上锁后检查。解决了忙则等待的问题，但是又违背了**空闲让进**和**有限等待**原则，会因各进程都长期无法访问临界区而产生“饥饿”现象（都进行了上锁，检查对方后都进行等待）。

### Peterson算法
皮特森算法(Peterson)，结合了单双标志法的思想。如果双方都想进入临界区，则尝试让出。
使用数组标识自己进入临界区的意愿，再使用变量指向对方的标号。如果对方的标号也指向自己且自己是**最后表示谦让**的进程，则由自己进行**循环等待**。执行完毕后将自身的意愿标识位设为false。
**没有遵循让权等待**，即使进不了临界区，也会占用CPU资源不停的进行while循环

### 中断屏蔽法
利用开/关中断指令实现，只要进程开始访问临界区就不可被打断。
优点：简单、高效
缺点：不适用于多处理机；只适用于操作系统内核进程，不适用于用户进程（只有内核进程才能使用这两个指令）

### TestAndSet指令
TS指令。也称TSL指令（TestAndSetLock），TSL指令通过**硬件实现**，具有原子性。
优点：将上锁和检查用硬件变成了一气呵成的原子操作，实现简单，无需严格检查是否有逻辑漏洞；适用于多处理机环境。
缺点：**不满足让权等待**，lock被上锁时，即使程序不能进入临界区，也会一直占住CPU忙等

### Swap指令
也叫Exchange指令，或简称XCHG指令
使用**硬件实现**，逻辑上和TSL指令是差不多的
优点：将上锁和检查用硬件变成了一气呵成的原子操作，实现简单，无需严格检查是否有逻辑漏洞；适用于多处理机环境。
缺点：**不满足让权等待**

### 互斥锁
解决临界区最简单的工具就是互斥锁，上锁和释放的执行必须具有**原子性**。每个互斥锁有一个布尔变量表示锁是否可用，不可用会被阻塞。
互斥锁最主要的缺点就是忙等待，有程序在临界区时，其他程序想要进入临界区就必须连续循环调用acquire验证锁是否可用。多个进程共享CPU时，浪费了CPU周期。因此互斥锁常用于多处理器系统，线程在同一个处理器上等待，不影响其他进程执行。
需要连续循环忙等的互斥锁，都可以成为**自旋锁**(spin lock)，例如TSL指令、swap指令、单标志法
需要忙等，时间片用完下处理机，违反让权等待
优点：等待期间不用切换进程上下文，多处理器系统中，若上锁时间段，则代价低
常用于多处理器系统，一个核忙等，其他核照常工作，快速释放临界区
不太适用于单处理机操作，忙等过程中不可能解锁


## 死锁
进程被互相阻塞，又无法达成解除的条件，就成为了死锁
并发环境下，各进程因为竞争资源而造成的一种相互等待对方手里的资源，导致**各进程都进入阻塞**，无法向前推进。如果无外力干扰，这些进程**始终无法向前推进**。这就是**死锁**
虽然饥饿和死循环也是由于无法得到想要的资源，无法向前推进，但还是有较为明显的区别的，饥饿是部分进程无法得到资源，死循环是该进程可以上处理机运行，但无法向前推进。
死锁和饥饿是管理者（操作系统）的问题，死循环是被管理者的问题
死锁的对象一定是2+，饥饿1+，死循环1+
产生死锁的条件：
1. **对象之间互斥条件**
2. **不剥夺条件**，只能由自己主动释放
3. **请求和保持条件**，保持了至少一个资源但又提出了新的资源请求，同时自己不释放
4. **循环等待条件**，存在进程的资源循环等待链

**发生死锁一定有循环等待，但是循环等待未必发生死锁**
**对系统资源的竞争**。各进程对不可剥夺的资源（打印机）的竞争可能引起死锁，对可剥夺的资源竞争是不会引起死锁的（CPU）
**进程推进顺序非法**。请求和释放资源的顺序不当会导致死锁
**信号量的使用不当**。如生产者-消费者问题中，如果实现互斥的操作P在同步P之前，就有可能导致死锁。

### 死锁处理策略
破坏死锁产生的四个必要条件
避免死锁：用某种方法防止系统进入不安全状态（银行家算法）
死锁的检测和解除：允许死锁发生，系统负责检测出死锁并解除

#### 预防死锁(静态策略)
##### 破坏互斥条件
**互斥条件**：将只能互斥使用的资源改成允许共享使用，系统就不会进入死锁状态，例如：**SPOOLing**技术。操作系统可以采用SPOOLing技术把独占设备在逻辑上改为共享设备。
SPOOLing技术是在进程和设备资源之间加入了一个**中间进程作为缓冲区**，也可认为是消息队列；其他进程**将作业托付给中间进程**，由中间进程统一交给打印机。
缺点是不是所有资源都可以改造，且为了系统安全性必须保护互斥性，很多时候无法破坏互斥条件

##### 破坏不剥夺条件
方案一：当进程请求新资源得不到满足时，必须立即释放当前保持的所有资源，之后需要再重新申请。即使资源尚未使用完毕也需要主动释放。
方案二：当某个进程需要的资源被占据时，可以由操作系统协助对想要的资源强行剥夺，需要考虑各进程的优先级。

缺点：
实现复杂
释放资源可能导致前一阶段的工作失败，因此一般只适用于易保存和恢复状态的资源，如CPU
反复申请和释放会增加系统开销，降低吞吐量
若采用方案一，只要得不到就需要一直释放再申请，可能导致饥饿。

##### 破坏请求和保持
已经拥有了部分资源，但又申请新的资源，而该资源被其他进程占据，进入阻塞，但是不释放已有资源
可以采用**静态分配方法**，运行前一次性申请完所有需要的资源，在资源未满足前不投入运行，投入运行后资源一直归其所有。
缺点：有些资源使用的时间可能很短，如果一直持有就会造成资源浪费，资源利用率低，可能导致部分进程饥饿。

##### 破坏循环等待条件
存在一种进程**资源的循环等待链**，链中每个进程已获得的资源同时被下一个进程请求
可采用顺序资源分配法，即每个进程必须按编号递增的顺序请求资源，同类编号相同的资源一次性申请完
原理：一个进程只有已经占有小编号的资源时，才有资格申请更大编号的资源。按此规则，已经有大编号资源的进程不可逆向申请小编号的资源，从而不会产生循环等待现象。
缺点：不方便新增设备，可能需要重新分配所有的编号；进程实际使用资源的顺序和递增顺序不一致，会导致资源浪费。

#### 避免死锁(动态策略)
##### 不允许死锁发生
**安全序列**指如果系统按这种序列分配资源，每个进程**都能顺利完成**。只需要找出一个安全序列，系统就是**安全状态**。当然，**安全序列可能有多个**。
如果分配资源后系统中找不出任何一个安全序列，系统就进入了**不安全状态**。意味着之后**可能**所有进程都无法顺利执行下去。当然，如果有进程提前归还了一些资源，那**系统可能重新回到安全状态**，不过一般考虑最坏的情况。
参考银行家算法，要考虑当前的序列分配后是否还能满足接下来的需求。

#### 检测和解除
##### 允许死锁发生
为了能够对死锁是否发生进行检测，必须：
1. 用某种**数据结构**保存资源的请求和分配信息
2. 提供**一种算法**，利用上述信息检测系统是否进入死锁
![分配简图](分配图.png)
如果通过回收再分配思想，当上图中可以消去全部边时，可认为处于安全序列。如果**不能消除所有边**，那么此时就发生了**死锁**。图中互为相反的边并不意味着只需要一单位资源，而是代表在已经有一单位资源的情况下再申请分配一单位资源。

算法：
1. 在资源分配图中找出既不阻塞也不是孤点的进程，消去其所有边，使之成为孤点。
2. 进程所释放的资源可以唤醒其他因为等待而阻塞的进程，如果能消去所有边，则称该图是**可完全简化**的。若此时不可完全简化，则认为会发生死锁。

检测出死锁的发生后，应该立即解除死锁
1. **资源剥夺法**，挂起至外存，释放其资源，要避免后续长时间挂起导致饥饿
2. **撤销进程法**（又称终止进程法），强制撤销部分甚至全部死锁进程，并剥夺资源。代价巨大。
3. **进程回退法**，让一个或多个死锁进程回退到足以避免死锁的地步。这就要求系统记录进程还原点

处理优先级：
1. 进程优先级
2. 已执行时间
3. 还要多久完成
4. 进程使用了多少资源
5. 进程是交互式的还是批处理式的


# 信号
**信号**(Signal)实现进程间通信(**IPC**, Inter Process Communication)
**信号量**(Semaphore)实现进程间的同步、互斥

信号(Signal)：用于通知进程某个特定事件已发生。进程收到一个信号后，对该信号进行处理
常见:SIGHUP、SIG**INT**（来自键盘的中断，例CTRL+C）、SIGQUIT、SIGFPE（浮点异常Float Point Exception）、SIGKILL（杀死进程）、SIGWINCH（窗口大小变化）、SIGPWR。对于异常则会终止并将错误信息转储内存，对于终止则终止
不同的操作系统对信号类型定义不一样，通常用宏定义常量表示信号名
进程控制块PCB中会有待处理信号pending和被阻塞信号blocked。blocked位向量也被称为信号掩码（signal mask）。
![](信号.png)
***用户进程之间可以发送信号，内核进程也可以给用户进程发送信号，甚至进程自己给自己发送信号***。常用于发送信号的函数为kill(pid_t pid,int sig)，**用户进程之间发送信号是有限制的**，例如SIGKILL（例如父进程杀死子进程）。进程并不能区分是谁发给自己的信号，也不能知道发送信号的先后。
每次**进程从内核态转换为用户态时**，都会**检查**是否有待处理信号，例如系统调用返回或中断处理返回。
检查方式为现将blocked按位取反，再与pending进行逐位与运算，最后得出来的就是需要处理的信号。上图中的8一开始就已经处于**阻塞态**，所以逐位与后8位为0。要阻塞的信号位由进程自己设置。
**流程**：进程收到信号->内核态回到用户态时，检测到待处理信号，转移到信号处理程序->运行信号处理程序->返回到下一条指令

## 信号处理
1. 执行操作系统为此类信号设置的缺省（默认）信号处理程序，有些信号默认忽略，不做处理
2. 执行进程为此类信号设置的**用户自定义信号处理程序**（自定义信号处理程序将覆盖1）
3. 信号处理程序运行结束后，通常会返回进程的下一条指令继续执行（除非信号处理程序将进程阻塞或终止）
4. 处理信号后，其对应的pending位会被**重置**为0，重复收到相同的信号时，后续的信号会被**丢弃**，因为仅有1bit位信号处理
5. 同时收到多个不同类的信号时，**优先处理位序小**的

每个进程都可以设置自己的信号处理程序，也可以设置自己的阻塞规则

### 信号与异常的关系
信号可以作为异常的配套机制，让进程对操作系统的异常处理进行补充；**有些异常无法由内核完成全部处理，可能还需要用户进程配合**。如果内核**可以完成全部处理，就不必再使用信号机制**。

## 信号量机制
进程互斥有四种软件实现方式：单标志法，双标志先检查法，双标志后检查法、Peterson算法
三种硬件实现方式：中断屏蔽方法、TS/TLS指令、Swap/XCHG指令
双标志法中，检查、上锁操作都无法一气呵成，导致两个程序都可能干扰对方判断
所有的解决方案都无法实现“让权等待”

用户进程可以通过使用操作系统提供的**一对原语**来对**信号量**进行操作，从而方便的实现进程互斥、进程同步。原语由操作系统提供，由**关中断/开中断指令实现**
**信号量**就是变量（可以是任意记录型变量），**可以用一个信号量表示系统中某种资源的数量**，例如用1表示有一台打印机。
例如：wait(S),signal(S)，常简称为**P、V操作**，来自荷兰语proberen(尝试)/verhogen(增加)。题目中常简写为P(S)/V(S)，分别对应阻塞进程和增加信号量。

### 整形信号量
用一个**整数型变量**作为信号量，用来**表示系统中某种资源的数量**。
资源够，变量>0则令变量--,否则在wait函数中进入循环等待。使用完资源后通过signal进行++。
依旧**忙等不让权**，一直占用处理机

### 记录型信号量
通过记录型数据结构表示的信号量，在数据结构中定义`剩余资源数，等待队列`两个变量，某进程需要使用资源时通过wait进行申请。如果资源以及不足，则主动调用block原语将申请进程从运行态进入阻塞态，并挂载到信号量对应的等待(阻塞)队列中。
任务完成后释放处理机，从等待队列中唤醒一个进程。
因为会主动阻塞自己，所以满足了让权原则，如果+1后剩余资源数仍小于1，证明有其他进程在等待。每次通过wakeup调出等待队列中第一个进程。

## 信号量机制实现互斥
1. 划定临界区，明确哪一段代码需要访问临界区
2. 设置互斥信号量mutex，初始值为1，进入前wait，进入后signal
3. 在进入区P(mutex)——**申请资源**
4. 在退出区V(mutex)——**释放资源**

对**不同的临界资源需要设置不同的互斥信号量**
P、V操作必须成对出现

## 信号量机制实现同步
让并发的进程有序推进
1. 分析什么时候需要实现同步，即保证代码运行的“先后顺序”
2. 设置同步信号量，初始为0，先进行释放资源，再进行申请资源
3. 如果后操作的代码没能申请到资源，则阻塞自身

对于指向同一个结果的多分支树，可以为每一对前驱关系都设置对应的同步信号量，要注意P、V的顺序

# 管程
信号量机制存在编写困难**易出错**的问题，需要严格核对顺序
管程是一种**高级同步机制**，更方便易用的实现同步和互斥，是一种特殊的**软件模块**，组成：
1. 局部对于该管程的**共享数据结构**的说明
2. 对该数据结构进行操作的**一组过程**（函数）
3. 对局部于管程的共享数据设置初始值的语句
4. 管程名字

管程的基本特征：
1. 局部于管程的数据只能被局部于管程的过程所访问
2. 一个进程只有通过调用管程内的过程才能进入管程访问共享数据
3. **每次仅允许一个进程在管程内执行某个内部过程**

**互斥操作由*编译器实现***

在Java中可以用关键字synchronized用来描述一个函数，这个函数在同一时间内就只能被一个线程调用。

当生产者因为缓冲区满而执行 `wait(full)` 时，它自身会被挂起，并释放管程锁，让其他进程可以进入管程操作共享缓冲区。此时，生产者处于阻塞状态，不占用 CPU。

当消费者执行 `remove` 并取走至少一个产品后，如果调用了 `signal(full)`，等待在 `full` 条件变量上的生产者会被唤醒。需要注意的是，**唤醒并不意味着生产者立即运行**。被唤醒的生产者首先会被加入就绪队列，等待调度器分配 CPU。只有当生产者重新获得管程锁后，它才能从 `wait` 返回并继续执行剩余的操作（如 `count++` 和 `insert_item(item)`）。

换句话说，signal 的作用是将等待进程标记为可运行，而真正执行还要依赖 CPU 调度和管程锁的获取。CPU 上可能还有其他进程在运行，因此生产者的继续执行会有一个延迟，并不是 signal 当刻立即占用 CPU。

可以用时间线理解整个过程：生产者 P 因满缓冲区阻塞，释放锁；消费者 C 取走一个产品并调用 `signal(full)`；此时 P 被唤醒并进入就绪状态；调度器选择 P 获得 CPU 并重新获取管程锁后，P 从 `wait` 返回继续执行。

一句话总结：**被 signal 唤醒的进程不会立即运行，而是进入就绪状态，只有重新获得管程锁并被调度器分配 CPU 后，才从 wait 返回继续执行。**
	3. **每次仅允许一个进程在管程内执行某个内部过程**

# 线程
在没有进程机制时，各个程序只能串行执行。引入进程后就可以异步并发执行程序了。
有些进程需要多开很多服务，而传统的进程只能串行的执行一系列程序。为此引入了“线程”，来增加并发度。例如QQ可以边聊天边视频边发文件。
***引入线程后，线程就成为了程序执行流的最小单位***，在这之前则是**进程**。
**每一个进程可以拥有多个线程，这些线程可以有各自不同的代码**

线程是一个**基本的CPU执行单元**，也是**程序执行流的最小单位**。引入线程之后，不仅是进程之间可以**并发**，进程内的**各线程之间也可以并发**，进一步提升了系统的**并发度**，使一个进程内可以**处理多任务**。
引入线程后，**进程**只作为**除CPU外的系统资源的分配单元**，如打印机、内存地址空间等

传统的进程间并发**需要切换进程的运行环境**，系统**开销大**。线程间并发，如果是同一进程内的线程切换，则不需要切换进程环境，系统**开销小**。引入线程后，并发带来的系统开销减小。

多CPU计算机中，各个线程可占用不同的CPU；每个线程都有唯一ID、和他的线程控制块（TCB）；线程也拥有三大基本状态；线程几乎不拥有系统资源（分配给进程的）；同一进程的不同线程共享进程的资源；由于共享内存地址空间，同一进程间的线程间通信无需系统干预；不同进程中的线程切换，会引起进程切换；同进程内线程切换开销小

## 线程的实现
- **用户级线程(ULT**, User-Level Thread)：用于早期操作系统，只支持进程不支持线程，由线程库实现的“伪线程”。通过对进程”线程库“内部自行实现的“伪线程”并发运行，实现了线程的机制。
用户级线程ULT是由应用程序通过线程库完成的，线程切换不需要用户态转变为内核态，因为是进程“线程库”在内部完成的线程切换，不需要请求内核指令。操作系统**意识不到线程的存在**，只知道线程库这个进程的存在。
优点：开销小，效率高，不需要切换CPU状态。
缺点：如果其中一个线程被阻塞，则其他线程无法被运行，CPU的**调度单位仍然是进程**，**并发性弱**

- **内核级线程(KLT**, Kernel-Level Thread,又称内核支持的线程)：此时是**操作系统层面**实施的线程，所以需要由操作系统介入管理工作和状态转换。
优点：线程是调度的基本单位，进程是资源分配的基本单位，线程阻塞后别的线程可以继续被执行。线程之间**并发能力强**
缺点：线程管理成本高，开销更大（线程管理需要让CPU进行状态转换）

## 多线程模型
**一对一**模型：一个用户级线程ULT映射一个内核级线程。每个用户进程有与用户级线程同样数量的内核级线程。
优点：一个线程阻塞后，别的线程可继续执行，**并发能力强**。多线程可在多核处理机上**并发执行**。
缺点：一个用户进程会占用多个内核级线程，线程切换**由操作系统内核完成**，需要**切换到核心态**，因此线程管理成本高，**开销大**。

**多对一**模型：多个用户级线程映射到一个内核级线程。且一个进程只被分配一个内核级线程。
优点：用户级线程切换只需要在用户空间内完成，不需要切换到核心态，开销小效率高。
缺点：用户级线程被阻塞后其他用户级线程无法运行，并发度不足，多个线程不能在多核处理机上并发运行。

**多对多**模型：多个用户级线程被映射到多个内核级线程上，用户级线程数量>内核级线程。
优点：既克服了多对一并发度不高的缺点，有客服了一对一模型中一个用户进程占用太多内核级线程，开销太大的缺点。

## 线程的状态和转换
和进程的状态与转换几乎是一样的，分为**就绪、运行、阻塞三大基本状态**。
![](线程状态.png)
TCB线程控制块中包含**线程标识符**(TID)，**程序计数器PC**（线程目前执行到哪里），**其他寄存器**(现成运行的中间结果)，**堆栈指针**（保存函数调用信息和变量），**线程运行状态**，**线程优先级**（调度和资源分配优先级）  ；  TCB中程序计数器PC，其他寄存器，堆栈指针构成了线程切换时需要保存/恢复的数据

# 调度
有多个待处理任务时，由于资源有限无法同时处理，此时则需要确立**某种规则**来决定**处理**任务的**顺序**。此为调度。
作业：一个具体的任务
用户向系统提交一个作业=用户让操作系统启动一个程序（来处理一个具体的任务）
**高级调度**（**作业调度**）。按一定的原则从外存的作业后备队列中挑选一个作业调入内存，并创建进程。**每个作业只调入一次，调出一次**。作业调入时会建立进程控制块PCB，调出时撤销PCB。

**低级调度**（**进程调度/处理机调度**）：按照某种策略从就绪队列中选取一个进程，将处理机分配给他。进程调度是操作系统中**最基本的一种调度**，在一般的操作系统中都必须配置进程调度。
进程调度的**频率很高**，一般几十毫秒一次。营造出一种并行的感觉。

内存不足时，可将某些进程数据调出外存，等空闲时或需要运行时再调入内存。
暂时调到外存等待的进程状态为**挂起状态**。被挂起的进程PCB会被组织成**挂起队列**
**中级调度**（**内存调度**）：按照某种策略决定将哪个处于挂起状态的进程重新调入内存。一个进程可能被多次调出、调入内存，因此**中级调度**发生的频率要比高级调度**更高**。

## 挂起状态与调度模型
暂时调入外存等待的进程状态为**挂起状态(挂起态, suspend)**
挂起态又可进一步细分为**就绪挂起、阻塞挂起**两种状态
此时五状态模型->七状态模型（创建、就绪、就绪挂起、运行、阻塞、阻塞挂起、终止）
挂起和阻塞的区别：虽然都是暂时不能获得CPU的服务，但是挂起态是将进程映像调到外存中去了，而阻塞态下进程映像还在内存中。
有的操作系统会将就绪挂起和阻塞挂起**分为不同的队列**，甚至根据阻塞原因不同再把阻塞挂起进程进一步细分多个队列。

## 进程调度的时机
**进程调度**（低级调度），就是按照某种算法从就绪队列中选择一个进程为其分配处理机
**需要进行**进程调度与切换的情况：当前运行中的进程**主动放弃**处理机和**被动放弃**处理机。
**主动放弃**：正常终止，运行时发生异常而终止，主动请求阻塞，例如等待I/O
**被动放弃**：时间片消耗完，更紧急的事情需要处理，有更高优先级的进程进入就绪队列

**不能进行**进程调度和切换的情况：
1. **中断处理过程中**。中断处理过程复杂，与硬件密切相关，很难在做到中断处理的过程中进行进程切换
2. 进程在**操作系统内核程序临界区**中
3. 在**原子操作过程中**（原语）。原子操作不可中断，有始有终。

*进程在**操作系统内核程序临界区**中**不能**进行调度与切换*，内核程序临界区而非普通程序临界区。
**临界资源**：一个时间段内只允许一个进程使用的资源。各进程需要**互斥访问**临界资源。
**临界区**：访问临界资源的代码，程序的代码轮流进入临界区
**内核程序临界区**一般使用于访问**某种内核数据结构**的，比如进程的就绪队列（由各就绪进程的进程控制块PCB组成）
一个进程处于内核程序临界区时，会将就绪队列进行上锁。此时的锁死为**无法分配CPU**，而非可被分配但无法被调出。
调度过程本质上是：`锁就绪队列->从就绪队列选一个进程->修改队列结构（出队）->解锁`
临界区的意义所在 👇
- 当前进程已经在**内核态**
- 它**持有就绪队列锁**
- CPU **继续执行当前进程的内核代码**，执行完成前拒不开锁
- **禁止或延迟调度**
也就是说：这是一个 **“非抢占 / 延迟抢占”窗口**

用户态下的普通临界区访问的临界资源会影响系统内核的管理工作，因此**在访问普通临界区时可以进行调度与切换**，例如I/O设备打印机。因为它只影响“资源互斥”，不影响“调度器自身的数据结构”.
- 同一时刻 **只能被一个进程使用**
- 属于 **慢速 I/O 设备**
- 使用时间长（毫秒级甚至更久）
所以操作系统会做两件事：
1. **互斥访问**：防止多个进程同时写打印机
2. **允许让出 CPU**：避免 CPU 空等打印机

如果**访问打印机时禁止调度**会发生什么？
- 打印一份报告要 3 秒
- CPU 因为“在临界区”不能切换
- 其他进程 3 秒 **完全饿死**
这显然是不可接受的。
👉 所以：
> **普通临界区必须允许调度，否则系统并发性会崩溃**

“必须整体完成”的代码——**临界区**。
**临界区不是“一段危险代码”，**  
**而是“访问共享状态时，必须保证原子性的那段代码”。**
“临界”不是说危险，而是说：
> **执行到这里，系统状态的正确性处在临界点上**。

一旦被打断、被并发执行：
- 数据就不再一致
- 系统就可能崩
所以：
> **临界区 = 对共享状态“动刀子”的那一段**

**临界区的本质不是“不让别人进”，**  
**而是“保证一个操作的原子性”。**
只要这段代码：  
中途被打断 + 别人进来  
会导致结果不确定或错误  
那它就是临界区。

**临界区是进程或线程中访问和修改共享资源的那段代码，**  
**为保证系统状态的一致性和正确性，**  
**在任一时刻只允许一个执行流进入该代码段。**
## 进程调度的方式
### 非剥夺调度方式
又称**非抢占方式**。即，只允许进程主动放弃处理机。在运行过程中即便有更紧迫的任务到达，当前进程依然会继续使用处理机，**直到该进程终止或主动要求进入阻塞态**。
实现简单，系统开销小但是无法处理紧急任务，适合早起批处理系统。


### 剥夺调度方式
**剥夺调度方式**，又称**非抢占方式**。当一个进程正在处理机上被执行时，如果**有一个更重要或更紧迫的进程需要使用处理机**，则立即暂停正在执行的进程，将处理机分配给更重要紧迫的那个进程。
可以优先处理更紧急的进程，也可实现让各进程按时间片轮流执行的功能（通过时钟中断）。适合于分时操作系统、实时操作系统。

## 进程的切换与过程
**狭义的进程调度**指从就绪队列中**选中一个要运行的进程**。（这个进程可以是刚刚被暂停执行的进程，也可能是**另一个进程**，后一种情况就需要**进程切换**）
**进程切换**是指一个**进程让出处理机，由另一个进程占用处理机**的过程。
**广义的进程调度**包含了选择进程和进程切换两个步骤。
进程切换的主要过程：
1. 对原来运行进程各种数据的保存
2. 对新的进程各种数据的恢复
（如：程序计数器PC、程序状态字、各种数据寄存器等处理机现场信息，这些信息一般保存在进程控制块）
**进程切换是有代价的**，因此如果**过于频繁**的进行进程**调度、切换**，必然会使整个**系统的效率降低**。使系统大部分时间都花在了进程切换上，而真正用于执行进程的时间减少。合适的切换频率可以提升并发性。

## 调度器和调度程序

时间片用完和被调度程序选中由调度程序引起，调度程序决定让谁运行（调度算法）和运行多长时间（时间片大小）。
调度时机（触发调度程序）：
1. 创建新进程
2. 进程退出
3. 运行进程阻塞
4. I/O中断发生

非抢占式调度策略，只有运行进程阻塞或退出才触发调度程序工作
抢占式调度策略，每个**时钟中断**或k个时钟中断会触发调度程序工作
在不支持内核级线程的操作系统，调度程序处理的对象是进程，反之为线程。

#### 闲置进程
CPU永远都是忙碌的，当**没有其他就绪进程**时，CPU会运行闲置(idle)进程
闲置进程优先级最低，可以是0地址指令，**占用一个完整指令周期**（周期末尾例行检查中断）
**能耗低**

**零地址指令是计算机指令系统中不设地址字段的指令格式，仅包含操作码**。 其操作数来源分为两类：无需操作数的控制指令（如空操作NOP、停机HLT）和操作数隐含在寄存器或堆栈中的运算指令（如子程序返回RET）。 该指令通过隐含寻址方式减少地址字段，可有效缩短指令长度，节省存储空间。 在堆栈结构处理器中，零地址指令通过栈顶和次栈顶元素默认完成运算。


## 调度算法
FCFS，SJF，HRRN适用于早期**批处理系统**，因为交互性很糟糕，也没有优先紧急事件机制
时间片轮转RR、优先级调度算法、多级反馈队列调度算法适用于**交互性系统**，更注重响应时间、公平性、平衡性等指标。
### 先来先服务(FCFS)
**先来先服务(FCFS**, First Come First Server)
按照作业/进程到达的**先后顺序进行服务**，等待时间越久越先被服务，因为**它们到得早，被迫等得久**
**一般是非抢占式**的算法
优点：公平，算法实现简单
缺点：**对长作业有利，对短作业不利**，当前者用时过长时，后者的短作业的带权周转时间就会很大
**不会导致饥饿**

### 短作业优先(SJF)
**短作业优先(SJF**, Shortest Job First)
追求更少的平均等待时间，最少的平均周转时间，最少的平均平均带权周转时间
最短的作业/进程优先得到服务，既可用于作业调度，也可用于进程调度(SPF, Shortest Process First，短进程优先算法)
SJF和SPF是**非抢占式**算法（***未声明则默认***）。**也有抢占式的版本——最短剩余时间**算法(SRTN, Shortest Remaining Time Next)

每次调度时选择当前**已到达且运行时间最短的作业/进程，同等运行时间的选择先到达的**，使用非抢占式时，要注意第一个到达的作业长度。
抢占式**最短剩余时间**算法SRTN时，**每当有进程加入*就绪队列改变时就需要调度***，如果新到达的进程**剩余时间**比当前运行进程**剩余时间**更短，则由新进程**抢占**处理机，当前进程回到就绪队列。当一个**进程完成时也需要调度**

***在所有进程几乎同时到达时，采用SJF调度算法的平均等待时间和平均周转时间是最少的***，否则是抢占式SRNT最短剩余时间算法最少

优点：“最短的”平均等待时间、平均周转时间
缺点：**不公平。短作业有利长作业不利。可能产生饥饿现象**。运行时间由用户提供，不一定真实，长作业可以拆分为多个小作业。有源源不断的作业、进程到来时，会饥饿。
### 高响应比优先(HRRN)
既考虑等待时间也考虑要求服务的时间
每次调度时先计算**响应比**，选择**响应比高的服务**
响应比=$\frac{等待时间+要求服务时间}{要求服务时间}$ ，这个值肯定大于等于1
**非抢占式**的算法。只有当前运行的作业/进程主动放弃处理机时，才需要调度，才需要计算响应比
这个算法不会导致饥饿
优点：综合了FCFS和SJF两种算法的性能
缺点：无明显缺点

### 时间片轮转(RR,Round-Robin)
公平、轮流地为各个进程服务，令每个进程在一定时间间隔内都可以得到相应。按到达就绪队列的顺序轮流让各个进程执行一个**时间片**（例如100ms）。执行完时间片则剥夺处理机，而后排序至**就绪队尾**。
用于进程调度（只有作业被放入内存建立了相应的进程后才能被分配处理机时间片）
属于**抢占式的算法**，由**时钟装置**发出时钟中断通知CPU时间片已到
时间片调度算法**常用于分时操作系统**，更注重响应时间
***如果下处理机和新到达发生在同一时刻，默认新到达的进程先进入就绪队列，下处理机的进程排在队尾***，除非题目作出说明

如果**时间片太大**，使每个进程都可以在一个时间片内完成，则时间片轮转调度算法**退化为先来先服务**调度算法，并且**会增大进程响应时间**。因此**时间片不能太大**。设有10个进程正在运行，时间片为1s，则末尾的进程需要经过9s才能被响应。
时间片也**不能太小**，否则会频繁地发生进程的调度、切换，无效时间开销增大
时间片大小参考一般为切换进程造成的开销不超过1%
优点：公平、响应快，适合分时操作系统
缺点：进程切换时会有一定时间开销，没有区分任务紧急程度

### 优先级调度算法
进程/作业有各自的优先级，先选择优先级最高的作业/进程
有**抢占式**，也有**非抢占式**，非抢占式只考虑是否放弃处理机，抢占式还需考虑队列变化时是否发生抢占，**队列发生变化时会再检测一次优先级**
**优先数**和**优先级**是两个概念，需要考虑优先数和优先级的对应关系，大/小对应的高/低
就绪队列未必只有一个，可以按优先级来组织。此外，也可以把优先级高的进程排在更靠近队头的位置。
有**静态优先级**和**动态优先级**，创建时会先定下初始值，动态优先级可以在后续进行调整
系统进程**高于**用户进程
前台进程**高于**后台进程
操作系统**更偏好I/O级进程，或称I/O繁忙级进程**；与其相对的是**计算级进程，或称CPU繁忙型进程**，I/O设备和CPU可以**并行**工作，I/O繁忙可以先让I/O设备尽早的投入工作，资源利用率和吞吐量都会得到提升

从追求公平、提升资源利用率的角度来看，可以令就绪队列中等待长的优先级提升，占用处理机时间长的优先级下降；进程频繁使用I/O设备时也可以提升优先级
优点：可以区分紧急程度和重要程度，适合实时操作系统，灵活调整偏好程度
缺点：可能导致饥饿，源源不断的高优先级会导致低优先级进程饥饿

### 多级反馈队列调度算法
对其他算法的折中权衡，**是抢占式的算法**，可能有非抢占式的版本
1. 设置**多级就绪队列**，优先级按队列从高到低，时间片从小到大(**最小优先级的队列时间片最大**，而非同一级后运行的时间片大)
2. 新进程到达先进入第一级，按**FCFS先来先服务原则**排队等候分配时间片，时间片用完还未结束时**进入下一级队列队尾**，如果已经在最下级，则**放回该队列（最下级）队尾**
3. 只有当前队列**为空**时，才会为下一级队头的进程分配时间片
抢占情况：当上一级队列进入新进程时，当前运行的进程放入该队列队尾，先运行上一级的新进程
优点：相对公平，每个新到达进程响应快，短进程完成快，不必实现估计进程的运行时间（避免用户作假，拆开大进程），可灵活调整对各级进程偏好程度
缺点：可能导致饥饿，有可能有源源不断的高优先级进程到来

队列之间可采取固定优先级或时间片划分。
固定优先级：高优先级先调度
时间片划分：三个队列分别分配时间50%、35%、15%
各队列可采用不同的调度策略，例如对于系统进程队列采用优先级调度，交互式队列采用时间片轮转调度RR，批处理队列采用先来先服务FCFS

### 多处理机调度
单VS多：
单处理机调度：只需要考虑让哪个就绪进程优先上处理机即可
多处理机调度：除了**使用调度算法决定**哪个进程上处理机外，还要考虑**上哪个处理机运行**
多处理机调度应该追求：**负载均衡**，尽可能让每个CPU都同等忙碌；**处理机亲和性**，尽可能让一个进程调度到同一个CPU上运行，以发挥CPU中缓存的作用(Cache)
尽确实可以减少进程切换带来的时间开销。本质原因在于 CPU 的高速缓存（Cache）和相关硬件状态具有**处理器本地性**。

进程在某个 CPU 上运行时，其指令和数据会逐步被加载到该 CPU 的 L1 / L2 Cache 中，同时页表映射会缓存在 TLB 中，分支预测器也会积累执行历史。如果进程在短时间内再次被调度到同一个 CPU 上运行，这些硬件状态往往仍然有效，从而减少 Cache miss 和地址转换开销，提高执行效率。

相反，如果进程在不同 CPU 之间频繁迁移，新 CPU 的 Cache 中通常缺乏该进程的指令和数据，原有 CPU 中的缓存内容也无法直接利用，会导致大量 Cache miss，需要重新从内存或更高层 Cache 中加载数据，间接放大了进程切换的实际代价。

因此，调度器通常会尽量保持进程的 **CPU 亲和性（CPU Affinity）**，即优先将进程调度回上一次运行的 CPU，以减少因迁移导致的 Cache 和 TLB 失效。这种做法在调度层面上最大程度地降低了切换对 Cache 局部性的破坏。

需要注意的是，这种策略主要减少的是**调度行为本身引起的 Cache 损失**，并不能完全决定程序的 Cache 利用率。Cache 是否高效利用，还取决于程序的内存访问模式、工作集大小以及多核系统中任务之间的竞争关系。

#### 公共就绪队列
将所有就绪进程放在同一个就绪队列中，所有CPU共享同一个就绪队列进程（位于内核区）
每个CPU运行调度程序时，从公共继续队列中选择一个进程运行
每个CPU访问就绪队列时是**互斥**的，会给就绪队列**上锁**，否则可能发生同时选中一个进程的情况。可以**天然的实现负载均衡**，每个CPU会尽量忙碌。
缺点：**亲和性不强**，进程会在不同的CPU上运行

改进：
- 软亲和：让调度程序使用特定的算法尽量保证亲和性
- 硬亲和：让用户进程通过系统调用**主动要求操作系统分配固定的CPU**，确保亲和性
#### 私有就绪队列
每个CPU有自己的私有就绪队列，空闲时运行调度程序，从私有队列选一个进程运行

***实现负载均衡***：
- 推迁移(push)：一个特定的系统程序周期性检查每个处理器的负载情况，负载不均衡则从忙碌的就绪队列中推一部分进程去空闲CPU的就绪队列
- 拉迁移(pull)：周期性检查自身与其他CPU的负载，如果自身负载低，则从其他高负载CPU就绪队列中“拉”一部分就绪进程到自己的队列中

私有就绪队列**天然的实现了处理机亲和性**，除非这个进程被负载均衡走了。当然**也可以硬亲和**。
在私有就绪队列中，CPU 只在本地队列中调度进程，通常采用抢占式的时间片轮转调度；先来先服务并非主要策略，仅在特定或退化条件下出现。
- RR 让多个进程共享一个 CPU 的 Cache
- 但同一进程每次被调度回来时：
    - 指令仍可能在 I-Cache
    - 热数据仍可能在 D-Cache
- 只要时间片不过短、进程数不过多，Cache 仍然是“半热甚至全热”
真正毁 Cache 的，是：
> **进程刚把数据放进 CPU0 的 Cache，下一次却被调度到 CPU5**

进程切换不会主动清空 Cache，Cache 只是“被动地被挤掉”。

## 调度算法评价指标
### CPU利用率
由于早期CPU造价极其昂贵，所以人们希望**让CPU尽可能多的工作**
CPU利用率：指CPU忙碌的时间占总市场的比例
**利用率**=$\frac{忙碌时长}{总时间}$

### 系统吞吐量
单位时间内完成作业的数量
**系统吞吐量**：$\frac{总共完成的作业数量}{总计时间开销}$ 道/每秒

### 周转时间
对于计算机的用户来说，更关心的是从自己的作业提交到完成花了多少时间
周转时间指**从作业提交给系统开始**，到**作业完成为止**的这段时间间隔，整个过程中只有一次高级调度（作业调度）
**作业周转时间**=$作业完成时间-作业提交时间$
**平均周转时间**=$\frac{作业周转时间之和}{作业数}$
对于操作系统，更关心整体表现，因此更关心所有作业周转时间的平均值，但用户可能会遇到极端情况，非常短和非常长，所以产生了**带权周转时间**
**带权周转时间**=$\frac{作业周转时间}{作业实际运行时间}$ （反映的是等待时间和运行时间之比）
**平均带权周转时间**=$\frac{各作业带权周转时间之和}{作业数}$

### 等待时间
用户会希望自己的作业尽可能少的等待处理机
**等待时间**，指进程/作业处于**等待处理机状态时间之和**，等待时间越长，用户满意度越低
作业调入内存后，**建立对应的进程**，这个进程会被CPU和I/O设备服务，也会有等待被服务的时间，包括在后备队列中等待被服务（调度）
对于**进程**来说，等待时间指进程建立后**等待被服务的时间**之和，在等待I/O完成期间进程也是在被服务的，不计入等待时间。
对于**作业**来说，不仅要考虑**建立进程后的等待时间**，还要加上在外存后备队列中等待的事件
和前文一样，不仅有等待时间，还有平均等待时间
等待时间=$周转时间-运行时间$
### 响应时间
对于计算机用户来说，会希望自己提交的请求尽快被系统服务、回应
**响应时间**，指从用户**提交请求**到**首次产生响应**所用的时间。

# 内存
内存(**R**andom **A**ccess **M**emory，**RAM**)可存放数据。程序***执行前都需要先被读入内存***中才能被CPU处理——***缓和CPU与硬盘之间的速度矛盾***
内存地址从0开始，**每个地址对应一个存储单元**。
如果计算机按**字节编址**，则每个存储单元大小为1字节，即1B，8个二进制位。
如果字长为16位的计算机按字编址，每个存储单元大小为1个字，则为16个二进制位。
内存单位的换算都是$2^{10}$为进制

## 装载
**装入程序**是操作系统提供的一个程序或功能，用于**把用户程序从外存（磁盘、文件）加载到内存**，为执行做准备。
- 分配内存空间（为程序找到可用的块或分区）。
- 将程序代码和数据从外存复制到内存。
- 做地址重定位（如果是动态装入或重定位作业）。
- 设置起始执行地址，启动程序。

**装入模块**是**经过编译、汇编和链接后的可执行程序文件**，它是装入程序要搬到内存的“对象”。
- 已经处理了符号链接、地址分配（可能是逻辑地址）。
- 包含程序的**指令、数据段、符号表等**。
- 是内存执行单元，OS 根据它来加载到内存。

1. **绝对装入**：在编译时，如果知道程序将放到内存中哪个位置，编译程序将提前产生绝对地址的目标代码。装入程序按照装入模块中的地址，将程序和数据装入内存。**只适合单道程序环境**。
2. **静态重定位**：又称**可重定位装入**。编译、链接后的装入模块地址都从0开始，指令中使用的地址、数据存放地址都是相对于起始地址而言的逻辑地址。可根据内存当前情况，将装入模块装入到内存的适当位置，装入时进行“重定位”，将逻辑地址变为物理地址。**必须分配其要求的全部内存空间**，如果没有足够的内存就不能装入该作业。进入内存后，**运行期间就不能再移动**，否则指针错误，也不能再申请内存空间。 适用于**早期批处理系统**
3. **动态重定位**：又称**动态运行时装入**。编译、链接后的装入模块地址都从0开始，装入程序把装入模块装入内存后，并不会立即进行逻辑转物理，而是**推迟到程序真正打算执行时才进行**。因此装入内存后所有地址依然是逻辑地址。这种方式需要一个**重定位寄存器**的支持。**现代操作系统使用**。
动态重定位可以**将程序分配到不连续的存储区**中；在运行前仅需装入部分代码即可投入运行，在运行期间根据动态申请分配内存；便于程序段共享，可以向用户提供比存储空间大的多的地址空间。
**不是靠指针把程序“串起来”的**  
**而是靠“地址映射表 + 硬件地址变换”**  ，映射表主要**关注块的首项和块的长度**，而不是每个单独的地址
程序本身看到的地址空间仍然是**连续的**，CPU 访问的从来不是物理地址，而是逻辑地址

编译：由编译程序将用户源代码编译成若干个目标模块（**将高级语言翻译为机器语言**）。
链接：将离散的编译后形成的目标模块，以及库函数链接在一起，形成一个完整的装入模块
装入（装载）：由装入程序将装入模块装入内存运行

1. 静态链接：在程序运行之前将各模块及其所需库函数链接成完整的可执行文件，之后不再拆开
2. 装入时动态链接：将个目标模块装入内存时，边装入边链接
3. 运行时动态链接：程序执行中需要该目标模块时才进行链接。便于修改和更新，还有实现对目标模块的共享。 

## 内存空间的分配与回收
操作系统负责**内存空间的分配与回收**
### 连续分配
分配的空间为连续的内存空间而非离散的
#### 单一连续分配
在单一连续分配方式中，内存被分为**系统区**和**用户区**。
内存中**只能有一道用户程序**，用户程序独占整个用户区空间。
实现简单，无外部碎片，内存**不一定**需要内存保护（例如MS-DOS）。
只适用于**单用户、单任务**的操作系统；有**内部碎片**；存储器**利用率低**。

内部碎片：未被利用的空闲存储区。

#### 固定分区分配
为了支持 **支持多道程序的系统**在内存中装入多道程序，且防止进程互相干扰，于是将**用户空间**划分为**若干个固定大小的分区**，**每个分区中仅装入一道作业**，这样就形成了最早的、最简单的一种可运行多道程序的内存管理方式。
***分区大小可以不相等***

操作系统需要建立一个数据结构——**分区说明表**，来实现各个分区的分配与回收，通常按分区大小分配。每个表项包括对应分区的**大小、起始地址、状态**。
如果用户程序想要装入内存，则检索分区说明表，从中找到大小满足且未被分配的分区。
优点：实现简单，**无外部碎片**
缺点：当用户程序太大时，可能所有的分区都不能满足需求，此时不得不采用覆盖技术来解决，但又会降低性能；会产生内部碎片，**内存利用率低**
减小内存分配单元的大小确实可以降低内部碎片的规模，但是分配单元越小
- 页数越多
- 页表越大
- TLB 压力越大
- 地址转换更慢
- 页太小 → 命中率下降
- 映射关系太碎
- 太小的单元 → I/O 次数增加
##### 分区大小相等
此种情况下缺乏灵活性，但是适用于**一台计算器控制多个相同对象的场合**，可以认为是一个管理系统，亦或是服务器对多台主机的形式

##### 分区大小不等
增加了灵活性，可以满足不同大小的进程需求
根据常在系统中运行的作业大小进行划分，例如划分多个小分区、适量的中分区、少量大分区

#### 动态分区分配
**动态分区分配**又称**可变分区分配**。这种分配方式**不会预先划分内存分区**，而是在进城装入内存时，**根据进程的大小动态地建立分区**，并使分区大小**正好适合**进程的需要。因此**系统分区的大小和数目是可变的**。
虽然动态重定位是最适合动态分区分配的，但并不意味着动态分区分配支持将作业分配入内存中物理上离散的分区。
***动态分区分配没有内部碎片，但是有外部碎片。*** 可以通过内存紧凑（拼接Compaction）技术来解决外部碎片。

操作系统中的内存使用情况使用**空闲分区表**或**空闲分区链**。
空闲分区表中记录了空闲区**起始地址**、**空闲区长度**、空闲区状态（可选）、**指针/连接信息**（实现相关）。其中**不记录已分配区域**，所以状态可选。
**空闲分区链中记录了：**起始地址**、**分区大小**、**前向/后向指针**（实现相关），可选地记录空闲区状态。由于链表只管理空闲分区，**不记录已分配区域**，所以状态信息是可选的。每个空闲分区的**起始部分**和**末尾部分**分别设置**前向和后向指针**，用于**将各空闲分区链接成双向链表**。起始部分通常记录该分区的**起始地址、分区大小**等管理信息；末尾设置的指针主要用于支持分区回收时向前查找相邻空闲分区，以便进行合并操作，从而减少外部碎片。空闲分区链可按地址顺序或按分区大小顺序组织，不同的组织方式将影响内存分配算法（如首次适应、最佳适应等）的实现效率。

把一个作业装入内存时，需按照一定的**动态分区分配算法**，从空闲分区表/链中选出一个分区分配给作业。由于分配算法对系统性能影响很大，因此人们对其进行了广泛的研究。

如果作业所需内存空间大小小于当前空闲分区大小，从空闲分区的 **低地址部分** 分配给作业。在空闲分区表中仅需调整分区大小与起始地址，在链中则是调整本块空闲分区。
如果作业所需内存空间大小等于当前空闲分区大小， **整块分配给作业**，在空闲分区表中**删除**对应的空闲分区表项 / 链表结点
如果作业所需内存空间大小大于当前空闲分区大小，不修改分区表/分区链，按分配算法查找下一空闲分区，若遍历结束仍无满足的分区，则分配失败。

##### 回收
对于表依旧是调整起始地址和更新分区大小，如果回收后导致两个空闲分区**相邻**，则表项**合并**，不相邻则看情况增添表项。
***表项的排序要看动态分配分区算法***。

#### 动态分区分配算法
如果有多个空闲的内存分区都可以满足分配需求？应该选择哪个分区？
查找成功则可认为是一次命中（fit）
##### 首次适应算法(First Fit)
每次都从低地址开始查找，找到第一个满足大小的空闲分区
**空闲分区以地址递增的次序排列**。每次分配内存时顺序查找**空闲分区表/链，找到大小能满足要求的第一个空闲分区**。虽然时间开销大，但是也隐含了最佳适应算法的效果。
##### 最佳适应算法(Best Fit)
由于动态分区分配是一种**连续分配方式**，为各进程分配的空间必须是连续的一整片区域。因此应当**尽可能的留下大空间**，优先使用小空间。
空闲分区**按照容量递增**（从小到大）。每次分配内存顺序查找空闲分区表/链，找到大小满足要求的第一个空闲分区。要注意大小变动后的分区次序重分配。
由于每次都选择最小的分区，**会留下越来越多的、很小的、难以利用的内存块，会产生很多外部碎片。**

##### 最坏适应算法(Worst Fit)
又称最大适应算法(Largest Fit)
为了解决最佳适应算法中会产生大量小碎片，所以优先使用最大的连续空闲区。**按照容量递减**的次序链接。每次分配内存时顺序查找链/表，找到满足大小的第一个空闲分区。
由于每次都选择最大的分区进行分配，**会导致较大的连续空闲区被迅速用完**，之后的大进程很可能无法放入内存。也可认为是产生了较大的外部碎片
##### 邻接适应算法(Next Fit)
首次适应算法每次都从链头开始查找，会导致低地址部分出现很多小的空闲分区，每次分配查找时都需要经过这些分区，增加了查找的开销。
如果每次都**从上次查找结束的位置开始检索**，就可大幅减小时间开销。
空闲分区以地址递增的顺序排列，每次分配内存时**从上次查找结束的位置**开始查找表/链，找到大小能满足要求的第一个空闲分区。
由于每一次都从上次结束的地方向后查找，这就**导致了高地址部分的大分区更频繁的被使用划分为小分区**，导致最后无大分区可用。


### 非连续分配
**页**是**信息的物理单位**。分页的主要目的是为了实现离散分配，提高内存利用率。分页仅仅是系统管理上的需要，完全是系统行为，**对用户是不可见的**。
**段**是**信息的逻辑单位**。分段的主要目的是更好地满足用户需求。一个段通常包含着一组属于一个逻辑模块的信息。**分段对用户是可见的**，用户编程时需要显式的给出段名。
页的大小固定且由系统决定。段的长度不固定，决定于用户编写的程序。

**分页**的用户进程**地址空间是一维**的，程序员仅需**一个记忆符**即可表示一个地址。`LOAD 1, <A> `=>`从某个地址A中加载一个数据` 
**分段**的用户进程**地址空间是二维**的，程序员在标识一个地址时，既要给出段名，也要给出段内地址。`LOAD 1,[A] | <B>` => `从指定的段A中加载该段中的某个地址B的数据`

段的共享通过**多个段表项映射到同一段基址**实现；  
段的保护通过**段表项中的存取权限和段长检查**实现。
***分段更容易实现信息的共享和保护***，如果想要实现共享，仅需要让各个进程的段表项指向同一个段即可实现共享。**不能被修改**的代码称为**纯代码**或**可重入代码**（不属于临界资源），这样的代码是可以共享的。**可修改的代码是不能共享的**（比如，有一个代码段中有很多变量，各进程并发的同时访问可能会造成数据不一致）

#### 分页存储
内存空间会被分为一个个大小相等的分区，每个分区就是一个页框/页帧/内存块/物理块/物理页面。每个页框都有相应的编号，即页框号/页帧号/内存块号/物理块号/物理页面号，标号从0开始。
进程的逻辑地空间也分为**与页框大小相等**的一个个部分，每个部分称为一个“**页**”或“**页面**”，每个页面有一个编号，即“页号”，**页号从0开始**.

操作系统**以页框为单位为各个进程分配**内存空间。进程的每个页面分别放入一个页框中。进程的**页面**与内存的**页框**有一一**对应**的关系。***可以不连续存放***。

操作系统为了得知进程在内存中存放的位置，会为每个进程建立一张**页表**。通常存储在进程控制块PCB中。
一个进程对应一张页表；进程每页对应一个页表项；每个**页表项**由“**页号**”和“**块号**”组成；页表记录进程**页面**和实际存放的**内存块**之间的**映射关系**。
**页→<页号，块号>→页框号**
**内存块(页框大小)=页面大小**。页框编号范围应该是0开始的，**所以数量-1=范围**
页号不占用字节，因为是类似数组的结构，只需要知道第一个页表项地址即可。逻辑上包含页号和块号，物理上实际仅存储了块号。
***页表记录的是内存块号，而不是起始地址***，如果想要知道起始地址需要使用块号\*起始地址。
**页表中的一项（页项 / Page Table Entry, PTE）通常包含：**
1. **页号（Page Number）**
    - 一般**不显式存放**
    - 由页表下标隐含表示
2. **物理块号 / 页框号（Frame Number）** ⭐
    - 逻辑页 → 物理页框的**核心映射信息**
3. **存在位（Present / Valid bit）**
    - 1：该页已在内存
    - 0：不在内存（会触发缺页中断）
4. **访问权限（Protection bits）**
    - 读 / 写 / 执行（R/W/X）
    - （有时）**特权级 / 用户态标志**
5. **访问位（Accessed / Referenced bit）**
    - 该页是否被访问过
    - 页面置换算法会用（如 LRU 的近似实现）
6. **修改位（Dirty bit）**
    - 页面是否被写过
    - 决定换出时是否要写回外存
#### 多级页表
**没有必要让进程的整个页表常驻内存**，进程在一段时间内可能只会访问某几个特定的页面。单级页表必须连续存放，因此页表很大时需要占用连续的多个页框。
将长页表进行分组，使每个内存块刚好可以放入一个分组，再将各组离散的放到各个内存块中。
为离散分配的页表再建立一张页表，称为**页目录表**，或称**外层页表**，或称**顶级页表**。
计算时要记得偏移量是从0开始的。
页表项中会有一个**标志位**，标志该页表是否**存在于内存中**
***若采用多级页表机制，各级页表的大小不能超过一个页面***
对于两级页表的***访存次数***，先后访问快表->页目录表->二级页表->三级页表->实际物理地址
#### 地址转换
虽然页面是离散存放的，但是页面内部是连续的。
如果要访问内部逻辑地址，则先找到对应的页号，再查找起始地址就可以确认逻辑地址的页内偏移量。**逻辑地址对应的物理地址=所在页面在内存中的起始地址+页内偏移量。**
页号 = 逻辑地址//页面长度
页内偏移量=逻辑地址%页面长度
假设计算机用32个二进制位表示逻辑地址，页面大小为4KB=$2^{12}$B=4096B
则前20位为页号，后12位为偏移量
![](页内偏移量.png)
这个特性可以让计算机更快的拆分出页块号和页内偏移量，页号范围和偏移量范围都是$2^n$位（n为其所占比特位）

#### 基本地址变换机构(页表相关)
基本地址变换机构可以借助进程的页表项将逻辑地址转换为物理地址
通常会在系统中设置一个**页表寄存器**(PTR)，存放**页表在内存中的起始地址F**和**页表长度M**。进程未执行时，页表的起始地址和页表长度**放在进程控制块(PCB)中**，当进程被调度时，操作系统内核会把它们放到页表寄存器中。
*系统设置页表寄存器，用于存放当前进程页表在内存中的基址及页表长度。进程未运行时，这些页表描述信息保存在 PCB 中；当进程被调度执行时，内核将 PCB 中的页表基址指针和长度装入页表寄存器，供 MMU 进行地址转换。*
页表本体：
- ❌ 不直接放在 PCB 里（太大）
- ✅ 放在 **内核空间的内存页中**
- 可能占 **多个页面**
PCB 中存的不是页表，而是：
- **页表基址寄存器的值（PTR / PTBR）**
- 或者指向页表的指针

查找过程：根据逻辑地址计算出页号和页内偏移量→判断页号**是否越界**(越界中断为内中断)→查询页表找到对应的页表项，确定页面存放的内存块号→通过偏移量算出在物理块上的实际地址。如果页号=页表项，也越界了，因为页表项范围=页表数-1
**页表项**（Page Table Entry, **PTE**）通常包含的内容：物理块号（页框号）、有效位、访问位、修改位、保护位
- **物理块号（页框号）**  
    指明该逻辑页当前装入的是哪一个物理内存块  
    → 这是形成物理地址时真正用到的数据
- **有效位（存在位 / 驻留位）**
    - `1`：该页**已在内存中**，页表项有效
    - `0`：该页**不在内存中**，或该页当前无效
- **访问位（引用位 / 使用位）**
    - 该页在最近一段时间是否被访问过
    - 常用于页面置换算法（如 LRU、Clock）
- **修改位（脏位）**
    - `1`：该页被修改过
    - `0`：该页未被修改
    - 决定缺页时是否需要写回外存
- **保护位（访问权限）**
    - 可读 / 可写 / 可执行
    - 用户态是否允许访问
    - 用于内存保护

理论上页表项长度为3B即可表示内存块号的范围，但是为了方便页表的查询，常常会让一个页表项占更多的字节，**使每个页面恰好可以装得下整数个页表项**。
**页表存放在内存中，位于内核空间，占据专门分配的页面，与进程的代码/数据页面完全分离**

##### PCB中关于页表的项
PCB 中**并不直接存放页表本体**，而是保存用于“定位和描述页表”的信息，这些信息在进程切换时会被内核装入页表寄存器，供 MMU 进行地址转换。

PCB 中通常包含**页表基址信息，即页表在内存中的起始地址**。这里保存的是一个**指针（地址值）**，用于指向页表所在的内核内存区域，而不是页表项数组本身。进程被调度运行时，该指针会被写入页表基址寄存器（PTR / PTBR）。

PCB 中还会保存页表长度或页表界限信息，用于表示页表中有效页表项的数量。这一项是**实际数据（整数）**，主要用于页号越界检查，在调度时同样会被装入相应的页表长度寄存器。

在支持多级页表的系统中，PCB 中通常只保存**最高级页表（如一级页表）的基址指针**，其余各级页表通过页表项间接索引得到。该基址同样以**指针形式**存储。

此外，PCB 中还可能包含与页表相关的控制信息，如页表级数、页表类型、页大小编号或地址空间标识符（ASID）等。这些内容均以**实际数据或标志位**形式存放，用于指导地址转换或 TLB 管理，但不直接参与页表项访问。

需要注意的是，PCB 中**绝不会**直接存放页表项数组或具体的页映射内容。页表作为独立的系统管理数据结构，存放在内核内存中，占用专门的页面，PCB 仅保存用于定位和管理页表的描述信息。

可以认为，在单级页表模型下，PCB 中保存的页表基址指向一段连续存放的页表项数组。页表长度用于描述该进程逻辑地址空间中逻辑页的数量，即页表中**有效页表项的个数**，从而**限定进程可访问的页号范围**，而不是表示页表的个数。

#### 快表(TLB)
TLB中仅存放页表项的副本，普通Cache存放的是其他数据的内容
**快表**又称**联想寄存器**（**TLB**，translation lookaside buffer）,是一种访问速度比内存块很多的高速缓存Cache(**TLB不是内存**)，用来存放**最近访问的页表项的副本**，可以加速地址变换的速度。与此相对的，内存中的页表常被称为**慢表**。TLB ≠ 简化版页表项
一条 TLB 表项通常包含：
1. **虚页号（VPN）**
    - 用来匹配逻辑地址中的页号
2. **物理页框号（PFN）**
    - 用来形成物理地址
3. **有效位**
    - 标识该 TLB 项是否可用
TLB 中常见的控制信息（很重要）
和页表项“高度相似”：
- **访问权限位**
    - 可读 / 可写 / 可执行
- **用户 / 内核态标志**
- **脏位（修改位）**
- **访问位（引用位）**
- **ASID（地址空间标识符）**
    - 用于区分不同进程的页号
    - 避免进程切换时清空 TLB
**先完成地址转换并返回物理地址给 CPU，同时（或顺带）把映射写入快表。**
- 无需关注完整物理地址本体，偏移量直接加上页框号形成最终物理地址
当CPU发起查询时，先尝试访问快表。如果快表中没有则查询内表（慢表），查询成功后**先**将物理地址返回给CPU，顺带复制一份存入外表中。**若快表已满，则按某种算法进行替换**。
 ![](查表例题.png)
 查表命中后还需加上**访问一次内存**的时间，所以查询内表需要有两个+100。如果支持**快表内表同时查询**时，快表未命中查询内表的时间应该合计为100，如果快表查到了就会**同步暂停**对内表的查询。

##### 局部性原理
**时间局部性**：如果执行了程序中某条指令，那不久后这条指令很可能再次执行；如果访问了某个数据，不久后可能再次访问，**因为程序中存在大量循环**。
**空间局部性**：一旦程序访问了某个存储单元，不久后其附近的存储单元也可能被访问，因为**很多数据在内存中是存放的**。

由于局部性原理，***可能连续多次查询到的都是一个页表项**。

#### 分段存储
与分页存储最大的区别就是离散分配时**地址空间的基本单位不同**
按照程序**自身的逻辑**关系划分为**若干个段**，每个段都有一个**段名**，每段地址从0开始编址。由于按逻辑功能模块划分，**用户编程更方便**，**程序的可读性更高**。
用户视角下是段名，CPU视角下是段号
分段系统的逻辑地址由**段名(段号)** 和**段内地址(段内偏移量)** 所组成

为了能从物理内存中找到各个离散存储的逻辑段位置，需要为每个进程建立一张段映射表，简称**段表**。
**段表中每一项通常包含的内容（字段/名字）是：**
1. **段号（Segment Number）**
    - 有时不显式存放，而是由段表下标隐含表示
2. **段基址（Base）**
    - 该段在**物理内存中的起始地址**
3. **段长（Limit / Length）**
    - 该段的**长度/大小**
    - 用于**越界检查**
4. **存取权限（Protection）**（可选，但很常见）
    - 读 / 写 / 执行权限
5. **存在位（Present / Valid）**（可选）
    - 表示该段是否已装入内存

**段号是从0开始**的，**段表长度至少是1**，所以段表长度必须大于段号。因为段长不同，所以在查找到段号后还会检查段内地址是否超过段长。两个判断中都会抛出越界中断异常。

#### 段页结合的分配方式
分页内存空间利用率高，**无外部碎片**，**有少量内部碎片**，不方便按照逻辑模块实现信息的共享和保护。
方便按照逻辑模块实现信息的共享和保护。段长过大，为其分配连续的内存空间会很不方便，**会产生外部碎片**。虽然可以用紧凑技术解决，但是需要付出较大的时间代价。

将进程按逻辑模块分段，再将各段分页。再将内存空间分为同等大小的内存块/页框/页帧/物理块，进程将各页面分别装入各内存块中。
段页式系统的逻辑地址结构由**段号、页号、页内地址（页内偏移量）** 组成，因此段页式管理的地址结构是二维的。

此时段表包**含段号、页表长度、页表存放块号(起始地址)**。段表**长度取决于进程的段数**，不同进程可以不同；段号通常不在段表项中显式存放，而是由段表索引隐含表示。每个段由于分页，其**最后一个页可能装不满**，因此**每个段最多产生一个内部碎片**。

#### 请求分页存储管理
**请求分页**和**基本分页**存储管理最主要的区别是：
1. 缺页中断时操作系统需要提供**请求调页**功能，**将缺失页面从外存调入内存**。*当访问的信息不在内存时，由操作系统负责将所需信息从外存调入内存，然后继续执行程序*
2. 操作系统需要提供**页面置换**的功能，将暂时用不到的页面换出外存，为了处理内存空间不足的问题。

为了实现**请求调页**，操作系统需要知道页面是否调入内存和在外存中的存放位置。当内存空间不足时，需要按照某种优先级指标来决定页面置换的页。记录各个页面是否被修改的信息。
所以页项应该含有**页号(隐含)、内存块号、状态位、访问字段、修改位、外存地址**。
状态位用于记录是否调入内存，访问字段记录的数据供算法选择换出页面时参考；修改位表示页面调入内存后是否被修改过。
***请求分页的页表被称作请求页表，普通页表为基本页表或“页表”***

缺页中断机构：**当访问的页面不在内存时**，产生一个缺页中断，然后由操作系统的缺页中断处理程序处理中断。此时**缺页的进程阻塞**，放入阻塞队列，调页**完成后再将其唤醒**，放回就绪队列。  如果内存中**有空闲块**，则为进程分配一个空闲块，将**所缺页面装入并修改相应页表项**；如果**没有空闲块**，则有**页面置换算法选择一个页面淘汰**，在内存期间**未被修改过的页面直接覆写**，被**修改过则需要写回外存**。
缺页中断属于**内中断**，**一条指令执行期间可能产生多次缺页中断**。

1. 请求调页（查到页表项时进行判断）
2. 页面置换（需要调入但无空闲内存块时）
3. 需要修改请求页表中新增的表项

查找流程：访问快表->访问请求页表->根据状态位决定下一步是**请求调页**还是**页面置换**  ；如果页表从内存中调出或被覆写，都需要修改快表
![请求分页地址变换过程](请求分页地址变换过程.png)
只有**写指令**才需要修改**修改位**，一般只需要修改快表中的数据，只有要将快表项删除时才需要写回内存中的慢表，可以减少访存次数。
缺页中断处理需要保留CPU现场。
需要用某种页面置换算法决定换出的页面。
换入换出都需要启动慢速的I/O操作，如果太频繁时间开销大。
页面调入内存后，需要修改慢表，同时也要将表项复制到快表中。

#### 页面置换算法
以访问字段位作为凭据而决定置换的顺序，访问字段可以是次数，也可以是最近一次的时间，具体看需求。
处理缺页中断时，如果有空闲块则不会发生页面置换，计算缺页率用$\frac{缺页中断次数}{总访问页面次数}$
**Belady异常**：只有FIFO算法会产生Belady异常，分配的物理块数增大时，缺页次数不减反增。
![页面置换算法优缺点](页面置换算法.png)
##### 最佳置换算法（OPT）
最佳置换算法(OPT, Optimal):每次选择**淘汰**的页面将是**以后永不使用**，或在**最长时间内不被访问的页面**，这样可以保证最低的缺页率；看哪一个页面被二次访问的间隔最长。
该算法需要**未来视**，是一个**理论上的最优参照**，页面最佳置换算法（OPT）**在真实系统中不可实现**；当发生缺页时，**淘汰”未来“最长时间内不再被访问的页面**。

最佳置换算法并不是“计算机提前知道未来”，而是“人类在已知完整访问序列的前提下，**事后计算出的理论最优结果**”。
##### 先进先出置换算法（FIFO）
每次选择**淘汰的页面**是**最早进入内存的页面**。
将调入内存的页面根据调入的先后顺序排队，需要换出时选择队头页面。队列的**最大长度取决于系统为进程分配了多少个内存块**。
**实现简单**，但是和实际运行规律不适应，先进入的页面可能最经常被访问，**算法性能差**；会产生Belady异常

##### 最近最久未使用置换算法（LRU）
最近最久未使用置换算法（LRU， least recently used）:每次被**淘汰**的页面是**最近最久未使用的页面**，访问字段应记录自上次访问以来所经历的时间t，每次淘汰max($n_t$),即最近最久未使用的页面。
手动计算时，逆向检索访问页面记录中最后一个出现的页号就是被淘汰的页面。
**性能好**，**时间开销大**
##### 时钟置换算法（CLOCK）
性能和开销较均衡，**时钟置换算法**又称CLOCK算法，或**最近未用算法**(NRU, Not Recently Used)
为每个页面设置**访问位**，再将内存中的页面都**通过链接指针链接成一个循环队列**。页面**被访问时访问位设置为1**.需要淘汰页面时，遍历页面，扫到1则改为0，**扫到0则淘汰**该页面。因此，简单的CLOCK算法**最多两轮扫描即可决定淘汰页面**.
##### 改进型时钟置换算法
**简单的时钟置换算法仅考虑一个页面最近是否被访问过**。事实上，如果被淘汰的页面没有被修改过，则不需要执行I/O操作写回外存。**只有被淘汰的页面被修改过时才需要写回外存**。
在其他条件都**相同**时，应该**优先淘汰没有被修改过**的页面，避免I/O操作。0表示没有被修改过。

最多会进行四轮扫描，条件都相同的最终结果时选择扫描到的第一个可被替换的结果。**先进行一轮不修改任何标志位的扫描未被修改且最近未被访问的页，如果失败则进行第二轮扫描，查找第一个最近未被访问但被修改的页面，同时将访问位设置为0**，反复进行上述操作，最多会执行四次扫描
最近没被访问和修改>最近没被访问被修改过>最近被访问过未被修改过>最近被访问和修改过

#### 页面分配策略
**驻留集**：指请求分页存储管理中**给进程分配的物理块的集合**。在采用了虚拟存储技术的系统中，驻留集大小一般小于进程总大小
**工作集**：在**某段时间间隔里实际访问页面**的集合。系统会根据窗口尺寸算出工作集，**工作集大小可能小于窗口尺寸**。实际运用中如果经过某一段时间检测发现进程工作集比实际窗口尺寸小，说明进程**局部性良好**，只需要分配3个以上的内存块即可满足进程的运行需要。
驻留集太小会导致缺页频繁，系统需要花大量的时间处理缺页，实际用于进程推进的时间很少。驻留集太大会导致多道程序并发度下降，资源利用率低。
一般来说，**驻留集大小不能小于工作集大小**，否则频繁缺页

**固定分配**：驻留集大小一开始就已经确定了，**大小不变**
**可变分配**：先为进程分配一定数目的物理块，进程运行期间可适当增加和减少，**即大小可变**

**局部置换**：发生缺页时只能选进程自己的物理块进行置换
**全局置换**：可以将操作系统保留的空闲物理块分配给缺页进程，也可以将别的进程持有的物理块置换到外存，再分配给缺页进程。

**全局置换不可能是固定分配**，会导致进程拥有的**物理块数量改变**。
固定+局部：很难在刚开始就确定应该为每个进程分配多少个物理块。
可变+全局：若无空闲物理块，则可选择一个未锁定的页面换出外存。采用此策略时，只要进程发生缺页，都将获得新的物理块。仅当空闲物理块用完时，系统才选择一个未锁定的页面调出。因为可能调出任何一个进程的页，**所以会导致被选中的进程拥有的物理块减少**，**缺页率增加**。
可变+局部：如果进程频繁地发生缺页问题，会为该进程多分配几个物理块，直到缺页率趋势适当程度；反之若缺页率低，则可减少分配的物理块数量。

##### 何时调入页面
**预调页策略**：根据局部性原理，一次调入若干个相邻页面比一次一个更搞笑。如果提前调入的页面大多数都没被访问，则又是低效的。因此可以预测不久后可能访问到的页面先调入内存，但成功率仅50%。所以这种策略**主要用于进程的首次调入，由程序员指出调入的部分**.

**请求调页策略**：进程在运行期间发现**缺页时才进行调入操作**。由这种策略调入的页面一定会被访问，因为一次仅一页，每次都需要磁盘I/O操作，所以I/O开销很大。

##### 何处调入页面
**对换区**是用于进程或页面换入换出的外存区域，在实际系统中通常通过 **swap 分区或 swap 文件**实现，因此在教材和考试语境下常将对换区直接称为 swap 区。
系统**拥有足够**的对换区空间时：调入调出都是在内存和对换区之间运行，速度快。进程运行前需要将进程相关数据从文件区复制到对换区。
系统**缺少足够**的对换区空间时：凡是不会被修改的数据直接从文件区调入，不会调出，下次需要时再从文件区调入即可。对于可能被修改的部分，换出时需要写回磁盘对换区，下次需要时再从对换区调入。

UNIX方式：运行之前与进程有关的数据全放在文件区，未使用的页面都可从文件区调入。若使用过的页面需要换出，则写回对换区，下次需要的时候从对换区调入。

**抖动**/**颠簸现象**：刚换入就换出，频繁地页面调度行为称为抖动或颠簸。产生抖动的**主要原因**是进程频繁访问的页面数目高于可用的物理块数（**分配给进程的物理块不够**）
分配太少会颠簸，太多会降低并发性。
## 内存空间的扩展
操作系统需要提供某种技术从**逻辑上对内存空间进行扩充**，用到了**虚拟性**
### 覆盖技术
为了解决内存大小不够的情况，最初引入了**覆盖技术**用于解决**程序大小超过物理内存总和**的问题。**覆盖技术**的思想为将**程序分为多个段**（模块），在内存中分为一个**固定区**和**若干个覆盖区**。需要常驻内存的主段放在**固定区**中，**调入后直到运行结束前都不再调出**。不常用的段放在**覆盖区**，需要用到的时候载入内存，不用的时候从内存中卸载（**调出**）。
**调用（覆盖）结构必须由程序员声明**，操作系统会自动完成覆盖。**对用户不透明**，增加了用户编程负担。

只用于早起操作系统中，但是模块化的思想还是留下的

### 交换技术
交换（对换）技术的设计思想：空间紧张时系统将内存中的某些进程暂时**换出**外存，将外存中某些已具备运行条件的进程**换入**内存（进程在内存和磁盘见动态调度）。
***PCB进程控制块是常驻内存的***，用来获知进程在外存中的位置。
**中级调度（内存调度）**，就是要决定将哪个处于挂起状态的进程重新调入内存。
换出外存等待的进程状态称为**挂起状态**（suspend）
挂起态又可细分为**就绪挂起、阻塞挂起**两种状态。

具有对换功能的操作系统中，通常把磁盘空间分为**文件区和交换区**两部分。**文件区**主要用于存放文件，追求存储空间的利用率，因此采用**离散分配方式**；**对换区**只占磁盘空间的小部分，**被换出的进程数据存放在对换区**。由于对换区的速度会影响系统整体速度，**因此对换区的空间管理主要追求换入换出速度**，采用**连续分配的内存空间**。***对换区的I/O速度比文件区更快。***
**交换发生**在运行进程多且内存吃紧的情况，而系统负荷降低就暂停。例如：在许多进程运行时经常发生缺页，就说明内存紧张，此时可以换出一些进程。如果缺页率明显下降，就可以暂停换出。
**优先**换出处于**阻塞态**的进程；可换出**优先级低**的进程，为了防止优先级低的进程在短时间内被反复换入换出，有的系统还会考虑进程在内存中的**驻留时间**。

***PCB进程控制块是常驻内存的***，用来获知进程在外存中的位置。

### 虚拟存储技术
传统存储管理方式具有**一次性**和**驻留性**，**作业必须一次性全装入内存后才能开始运行**。作业很大时无法全部装入，导致运行失败。大量作业要求运行时，由于内存无法容纳所有作业，因此只有少量作业能运行，导致多道程序并发度下降；作业一旦被装入内存就会一直驻留在内存中，直至运行结束，导致内存中驻留了大量暂时用不到的数据，浪费了内存资源。

根据**时间局部性**和**空间局部性**的特性，可以将很快会用到的部分装入内存，暂时用不到的留在外存。程序执行时，访问的信息不在内存时由操作系统将所需信息调入内存，然后继续执行程序。如果空间不足则由操作系统负责将内存中暂时用不到的数据换出外存，在操作系统的管理下，用户似乎有一个比实际内存大的多的内存，这就是虚拟内存技术。

虚拟内存有以下三个特征：
1. 多次性：无需一次性全装入内存，允许拆分作业
2. 对换性：在作业运行时无需常驻内存，允许在运行过程中换入和换出
3. 虚拟性：逻辑上扩充了内存的容量，使用户看到的内存容量远大于实际容量

#### 如何实现虚拟内存技术
因为允许一个作业分多次调入内存，如果采用连续分配方式会不方便实现。所以虚拟内存的实现需要**建立在离散分配的内存管理方式基础上**。
操作系统需要在基础的管理方式上增添**请求调页或请求调段**的功能，还有**页面置换或段置换**功能

## 地址转换
操作系统需要提供地址转换功能，负责程序的**逻辑地址和物理地址的转换**。
为了使编程更方便，程序员写程序时只需要关注指令、数据的逻辑地址。而**逻辑地址到物理地址的转换**（这个过程称为**地址重定位**）应该由操作系统负责，这样就保证了程序员写程序时不需要关注物理内存的实际情况。

## 内存保护
操作系统需要提供**内存保护**功能。保证各进程在各自存储空间内运行，互不干扰。
方法一：在CPU中设置一对**上、下限寄存器**，存放进程上下限地址。进程的指令
要访问某个地址时，**CPU会检查是否越界**。
方法二：采用**重定位寄存器**（又称**基址寄存器**）和**界地址寄存器**（又称限长**寄存器**）进行越界检查。重定位寄存器中存放的是进程**起始物理地址**，界地址寄存器存放的是进程**最大逻辑地址**（反应了逻辑地址的范围）。

## 进程的内存映像
从高到低看，内存中的区域分为：**操作系统内核区**、**用户区**（用户栈、共享库的存储映射区、堆、可读/写数据区，只读代码/数据区、**未使用区**）
对于32位系统来说，操作系统内核区(0~0xC000 0000)这一块存储操作系统的内核数据，例如内核代码，内核数据结构，PCB进程控制块。这一块区域也称为**高地址区**。
内核区域下方为**用户区**。
用户栈由各个函数的栈堆组成，包含各个函数的局部变量、函数调用的相关信息。
共享库的存储映射区
**堆**，主要为malloc所分配的区域。对于**32位**地址来说，下三块区域总和**仅有1GB大小空间可供使用**。
低区域上方会有一块存储可以进行**读/写的数据区域**，例如普通和全局变量。
底部的**低区域为只读代码/数据**，主要用于**存放机器指令**。这里存放的也会有用户定义的**常量**等。
下方的**两块区域**在进程启动时就**固定**了大小。下三块空间总和不得大于1GB。用户区中**上两块区域**大小可变，但是在**32位**地址区域中仅占**2GB**大小。

**宏定义**在预处理阶段完成**文本替换**，不产生对象与符号，也不参与内存布局，因此不会也**不可能被存储进只读代码区或只读数据区**。
**CONST定义的会存储进只读代码/数据区。**

## 内存映射文件
操作系统向上层程序员提供的功能（**系统调用**）
传统文件访问方式（open / read / write / 移动指针seek）下，操作系统只会把「被修改过的页」写回外存，而不是读多少就写多少。
通过内存映射文件，文件访问方式被简化为内存访问。进程在 `open` 打开文件后，调用 `mmap` 将文件**映射到进程的虚拟地址空间**，随后即可**像访问普通内存一样访问文件数据**，通过「起始地址 + 偏移量」定位文件中的任意位置。此时**仅建立了地址映射关系，文件内容尚未读入内存**，页面处于缺页状态；实际的数据读入与写出由操作系统在缺页中断时**自动完成**。当进程关闭文件或映射被撤销时，操作系统会将**被修改的映射页**写回磁盘。
多个进程**映射同一个**文件，可以**实现共享**
*只要 CPU 要处理或修改数据，数据就必须先进入内存；但是否需要‘写回外存’，取决于你是否修改了数据，以及写回策略。*
*硬盘数据不能被 CPU 直接操作，所有参与运算的数据都必须先进入内存；但写回外存通常是延迟进行的，并非每一次操作都立即发生。*

## 文件系统的层次结构
由高到低分别为：
- 用户接口
- 文件目录系统
- 存取控制模块
- 逻辑文件系统与文件系统缓冲区
- 物理文件系统
- 辅助分配模块、设备管理模块，这两个模块在同一层
- 设备，在设备管理模块之下

文件系统需要向上层的用户提供一些简单易用的功能接口，用户接口层用于**处理用户发出的系统调用请求**。
用户是通过文件路径访问文件的，因此文件目录系统此层需要根据用户给出的路径查找相应的FCB或索引结点，**所有和目录、目录项相关的管理工作都在本层完成**。
存取控制模块**实现保护数据安全性**和**权限核验**。
逻辑文件系统和文件信息缓冲区中，用户指明想要访问的文件记录号，该层负责***记录号*和逻辑地址的转换**。
物理文件系统为上层的逻辑地址转换**提供实际的物理地址**。
**辅助分配模块**用于负责文件存储空间的管理，即**分配与回收空间**。**设备管理模块**直接与硬件交互，如分配设备、分配设备缓冲区、磁盘调度、启动释放设备等。
## 文件系统布局
**物理格式化**，即**低级格式化**，简称低格。会划分扇区，检测坏扇区，并用**备用扇区替换坏扇区**。
*操作系统视角下并不知晓坏扇区。*
**逻辑格式化**，即**高级格式化**。逻辑格式化后，磁盘分区(分卷)，完成各分区的文件系统初始化。逻辑格式化后，就产生了一些信息。

- 逻辑格式化的本质是在**已有分区内部建立文件系统结构**，不会改变磁盘物理扇区结构，也不会修改整块磁盘的第 0 扇区。
- 逻辑格式化后，分区内会生成：
    - 文件系统引导扇区（包含 BPB 等参数）
    - 文件分配管理结构（如 FAT 表、MFT、inode 表等）
    - 空闲空间管理信息（位图或链表）
    - 根目录结构
- 例如：
    - 在 FAT32 中会建立 FAT 表和根目录区
    - 在 NTFS 中会建立 MFT 和日志文件
    - 在 ext4 中会建立超级块和 inode 表
- 主引导记录（Master Boot Record）位于整块磁盘的 LBA 0，包含引导代码和分区表，不属于某个分区内部结构。
- MBR 通常在以下阶段写入：
    - 初始化磁盘（如使用磁盘管理工具创建分区表时）
    - 安装操作系统时（如 Windows 10 或 Ubuntu 的安装程序）

一个分区在逻辑格式化后会产生文件系统的基础结构，包括引导扇区（或预留引导块）、超级块、空闲空间管理结构、inode 区以及根目录。
即使不是系统盘，分区在逻辑格式化时通常仍然会**预留**或写入一个“引导扇区”。  
但这里的“引导块”多数情况下只是：
- 文件系统参数区
- 或预留空间

## 文件系统在目录中的结构
近期访问过的目录文件会**缓存**在内存中，不用每次都从磁盘读入，可以加快检索速度。
**用户打开文件表**：又称进程打开文件表，每个进程都拥有自己的打开文件表。
**系统打开文件表**：由操作系统所有，独一无二

- ① 解析路径名
    - 从当前工作目录或根目录开始逐级查找目录项
    - 每级目录项中保存“文件名 + inode 号（或 FCB 指针）”
    - 若路径中某一层不存在，则返回错误


- ② 读取 inode / FCB
        - 根据目录项中的 inode 号读取 inode（若不在内存则从磁盘调入）
    - 检查文件类型（普通文件 / 目录 / 设备文件）
    - 校验访问权限（r / w / x）
    - 若权限不满足，拒绝打开


- ③ 检查系统级打开文件表（System-wide Open File Table）
    系统通常维护两级结构：
    1. 系统级打开文件表（全局）
    2. 进程级文件描述符表
    在系统级表中会**创建或复用**一个表项，内容包括：
    - 指向 inode 的**指针**
    - 当前文件偏移量（file offset）
    - **访问模式**（只读 / 只写 / 读写）
    - **打开计数**（引用计数）
    - 文件**状态标志**
    若该文件已被其他进程打开
    - inode **不会重复创建**
    - 打开计数 +1
        

- ④ 在进程文件描述符表中分配条目
    - 为当前进程分配一个最小未使用的文件描述符 fd（如 3、4、5…）
    - 该 fd 指向系统级打开文件表中的对应表项
    进程只持有 fd，不直接操作 inode。

- ⑤ 返回文件描述符
    成功则返回 fd；失败返回 -1 并设置错误码。

补充几点关键机制：
- 多个进程打开同一文件：
    - 共享 inode
    - 但通常各自拥有独立的“文件偏移量”（如果是独立 open）
- 若通过 fork 继承文件描述符：
    - 父子进程共享同一个系统级打开文件表项
    - 因此共享同一个文件偏移量
- 在类 UNIX 系统（如 Linux）中，这套结构是典型实现模型。

## 文件的逻辑结构
用户视角下的文件结构，算法的具体实现与**逻辑结构和物理结构**有关。

**无结构文件**：数据由一系列**二进制流或字符流**组成。
**有结构文件**：由一组相似的记录组成，又称“**记录式文件**”。每条记录由若干个数据项组成，通常会选取其中一个数据项作为**关键字**（用于识别不同记录的 ID）。  
根据各条记录的长度（占用的存储空间）是否相等，又分为**定长记录**和**可变长记录**。
实际使用中，**可变长记录**较多。

**顺序文件**：文件中的记录**在逻辑上**一个接一个顺序排列，记录可以是定长的，也可以是可变长的。记录在物理上既可以**顺序存储**，也可以**链式存储**。

顺序文件又分为**串结构**和**顺序结构**：
- 对于**串结构**，记录之间的顺序与关键字无关（通常按存入时间排列，也可以理解为是队列存储的形式）；
- 对于**顺序结构**，记录之间按关键字顺序排列。

在**链式存储**方式下，无法实现随机存取，只能从第一个记录开始依次遍历。

**可变长记录一般无法直接实现随机存取**，通常需要从第一个记录开始遍历；  
**除非显式地记录每条记录的长度或位置信息**，否则无法通过简单的地址计算实现随机存取。

在**定长记录**下，**串结构无法快速找到关键字对应的记录**；  
若采用**顺序结构**，则可以较快地找到某一关键字对应的记录，例如使用**折半查找**。

一般而言，教材中提到的“**顺序文件**”多指**物理上顺序存储的顺序文件**。  
其缺点是：**增加或删除记录不够方便**，尤其是在顺序结构下。

对于**串结构**而言，新增记录时只需将新记录追加到文件末尾即可，相对简单。


## 文件的物理结构
类似于内存分页，磁盘中的存储单元会被分为一个个“块/磁盘块/物理块”。在很多操作系统中，**磁盘块大小和内存块、页面块大小相同**（规格化）。
内存中进程的逻辑地址空间被划分为页面，外存中为方便对文件数据的管理，**文件的逻辑地址空间也被分为了一个一个的文件“块”**。
文件的逻辑地址可以表示为（**逻辑块号**，**块内地址**）的形式

### 连续分配
**连续分配**方式要求**每个文件在磁盘上占用一组连续的块**。用户在操作自身文件时，主要操作的是逻辑块号、块内地址。
对于用户的文件操作，文件目录中记录的主要字段为文件名、**起始块号**、**长度**。
用户给出逻辑块号，操作系统去查找该文件对应的目录项（文件控制块）**物理块号=起始块号+逻辑块号**。依旧需要检查用户提供的逻辑块号是否合法。
因为可以直接算出逻辑块号对应的物理块号，因此连续分配支持顺序访问和直接访问（随机存取）

磁盘读取磁盘块时，需要移动磁头。访问的两个磁盘块**相隔越远**，移动磁头所需**时间越长**。所以连续分配的文件在顺序读取时是最快的。

由于采用连续分配方式，导致**不方便文件拓展**，需要**整体**移动到空闲的磁盘块中。**存储空间利用率低**，会产生大量难以利用的**磁盘(外部)碎片**。可以用**紧凑**来处理碎片。但是开销大。

### 隐式链接分配
***无描述默认为隐式链接分配***
**链接分配**采用离散分配的方式，可以为文件分配离散的磁盘块。分为**隐式链接**和**显式链接**两种。
除了文件的最后一个磁盘块外，每个磁盘块中都会保存**指向下一个磁盘块的指针**。文件的目录项FCB文件控制块中记录了文件的起始块号和结束块号，也可以增加一个字段用以表示文件的长度。

***起始块号为0，所以查询块号为i的磁盘块需要I/O操作次数为i+1***，采用链式分配（隐式链接）方式的文件**仅支持顺序访问不支持随机存储**。
**方便拓展**，**外存利用率高**，不会有碎片问题

### 显式链接分配
隐式中是指针保存在磁盘块中，显式中会将链接文件各物理块的指针存放在一张表中。即**文件分配表**（FAT，File Allocation Table）
其中主要的字段为：**簇号(可隐)、下一数据块（簇）的编号或结束标志**。
``` fakeCode
文件A:
簇5 → 簇9 → 簇12 → EOF
FAT中表现为：
FAT[5]  = 9
FAT[9]  = 12
FAT[12] = EOF
簇号 | FAT表项值 | 含义
--------------------------------
0    | FFF8      | 保留
1    | FFFF      | 保留
2    | 0003      | 指向簇3
3    | 0007      | 指向簇7
4    | 0000      | 空闲
5    | 0006      | 指向簇6
6    | FFFF      | 文件结束
7    | FFFF      | 文件结束
8    | 0000      | 空闲
9    | FFF7      | 坏簇
10   | 0000      | 空闲
11   | 0000      | 空闲
12   | 0000      | 空闲
13   | 0000      | 空闲
14   | 0000      | 空闲
15   | 0000      | 空闲
```

***一个磁盘仅设置一张FAT，在开机时读入内存并常驻。*** 因为FAT表项是连续存储，所以簇号字段可隐含。逻辑块号转换成物理块号的过程不需要I/O操作，直接对着内存中的FAT表查即可，所以想要访问指定的物理块仅需一次I/O操。
**支持随机访问**，外存利用率高，无外部碎片，方便拓展
文件分配**表需要占用一定存储空间**。

### 索引分配
**索引分配**允许文件离散的分配在各个块中，系统会为文件**建立索引表**，索引表中记录了文件的各个逻辑块对应的物理块。索引表存放的磁盘块称为**索引块**，文件数据存放的磁盘块称为**数据块**。

**目录项中会记录**索引块的磁盘块号。索引表是**连续分配**（逻辑块号可隐藏）的，**索引块必须等于磁盘块大小**。如果逻辑上需要更大的索引空间，则采用**多级索引表**、**链式索引块**、**组合索引**任意一种思想。

**支持随机访问，拓展容易实现**。
索引表需要额外的**空间开销**。

链式：**块尾**指向另一个索引块，如果想要查找**索引号较大**的磁盘块，则需要**大量时间开销**（遍历）
**多级索引表**：若**顶级索引表未调入内存**。要注意读表完了访问的时候总I/O次数为索引表层数+1
**组合索引**：混用了多级索引表和普通索引表，按层级顺序逐级使用，容量不够才向上升级。分为直接索引、n级间接索引。**对于小文件的I/O操作比多级少**
- 小文件 → 只用直接索引 L < 12
- 中等文件 → 用一级 12 ≤ L < 12 + N
- 大文件 → 用二级 12 + N ≤ L < 12 + N + N²
- 超大文件 → 用三级

## 逻辑vs物理
在用户视角下，整个文件占用了一片连续的逻辑地址空间。用户通过逻辑地址访问文件，寻找物理地址交给CPU处理。操作系统视角下就是纯比特流。

## 索引表
**索引表是连续存放的**。

**索引表**本身是由**定长记录组成的顺序文件**，因此可以通过下标快速找到第 _i_ 个索引项。  
在增删记录时，需要对索引表进行相应的修改。  
由于索引文件检索速度快，主要用于**对信息处理及时性要求较高的场合**。  
同一个文件可以基于不同的数据项建立多个索引表。

索引表一般由**索引号、记录长度、指针（或地址）**等字段组成。

**索引顺序文件**是索引文件思想与顺序文件思想的结合：  
为文件建立索引表，但并不是**每个记录对应一个索引项**，而是**一组记录对应一个索引表项**。

### 多级索引表
在索引表的基础上进一步进行划分与组织。  
最高一级称为**顶级索引表**，其下依次为**低级索引表**，用于减少查找范围、提高检索效率。

## 文件目录
对于用户视角，文件之间的组织结构清晰，易于查找，用户可以轻松实现按名存取
目录本身就是一种**有结构的文件**，由一条条记录组成。每条记录对应一个在该目录下的文件。对于文件主要拥有的属性：文件名、标识符、**类型**、创建、上一次修改时间、文件所有者信息、保护信息、存放位置这些内容中，类型属于目录。

**目录表**：操作系统用来管理目录内容的数据结构。
- 每个目录在文件系统中其实是一个特殊的文件，里面存放**目录项（记录）**。
- 目录项通常包含：文件名、文件类型、inode号、权限等。
- 操作系统通过目录表快速找到目录下的文件或子目录。
***目录文件中的每一条记录都是一个文件控制块（FCB）***，一个FCB就是一个文件目录项，FCB的有序集合为文件目录。FCB中含有**文件名**、**物理地址**、逻辑结构、物理结构等，还包含存取控制信息，使用信息（建立、修改时间）

用户调用 `open()` 或 `opendir()` 请求打开某个目录，系统调用触发后 CPU 从用户态切换到内核态。内核从根目录开始对路径进行解析，在每一级目录文件中查找对应名称的目录项（文件名到 inode 的映射），并在解析过程中对每一级目录执行权限检查。路径解析完成后，内核定位到目标目录对应的 inode，若该 inode 尚未在内存中则从磁盘读入。随后内核为该目录建立相应的打开文件数据结构（如 file、dentry 等），最后向用户态返回文件描述符或目录流，用于后续读取目录内容。

双击某个目录后，系统会在目录表中查找对应目录项（记录），根据目录项中的关键字定位信息，并将相关数据读入内存进行展示。

目录操作：
- **搜索**：当用户要使用文件时，系统要根据文件名搜索目录，找到该文件对应的目录项
- **创建文件**：需要在所属目录中增加一个目录项
- **删除文件**：当删除一个文件时，需要删除对应目录项
- **显示目录**：用户可以请求显示目录内容，例如其属性和所有文件
- **修改目录**：某些文件属性保存在目录中，因此属性变化时需要修改对应目录项（例如重命名）

### 单级目录结构
早期系统不支持多级目录，整个系统中**只建立一张目录表**，每个文件占一个目录项。
单级目录实现了**按名存取**，但是**不允许文件重名**。创建时先检查是否重名，然后将新文件对应的目录项插入目录表中。
很不适合多用户系统

### 两级目录结构
早期的多用户操作系统，采用两级目录结构。一个**主文件目录**(MFD, Master File Directory)和**用户文件目录**(UFD, User File Directory)
可以认为是一种高度为3的树，根节点为主文件目录
主文件目录记录**用户名**和其**用户文件存放位置**，用户文件目录则由该用户的文件控制块**FCB组成**
允许**不同用户**的文件重名
可以在目录上实现访问限制，检查登录用户的用户名是否与文件名匹配。依旧不够灵活，用户自己不能进行分类

### 多级目录结构
现代操作系统所使用
**从根目录出发**的路径是**绝对路径**。
文件路径名是个字符串，各级目录之间用“/”隔开
允许同用户拥有重复的文件名
```
/home/user1/report.txt
/home/user2/report.txt
```
两个 report.txt 文件名相同
但路径不同 → 组合成 **唯一标识符**

**文件标识符**保证在文件系统中每个文件 **有唯一元信息**，**目录表 + 多级路径**实现对重名文件的管理
内核根据目录表找到对应的 inode → 唯一确定文件


每一个"/"都意味着系统需要进行一次I/O操作，系统**逐级**查目录表，每一级可能触发 I/O 来获取下一层目录或文件的物理位置。直到命中目标文件为止。例如`/home/user2/report.txt`就进行了三次读I/O操作。

为了优化上面那种低效的多级查找方式，引入了“**相对路径**”的概念。如果这张目录表已经调入内存，则可将其设置为**当前（工作）目录**。当用户想要访问某个文件时，可以使用**从当前目录出发**的**相对路径**

***树形目录结构可以很方便的分类，层次结构清晰，安全性管理更有效。但是树形结构不适合实现文件共享，因此提出了“无环图目录结构”***

### 无环图目录结构
在树形结构的基础上增加了一些指向同一个节点的有向边，使整个目录成为一个“**有向无环图**”，可以更方便的实现多个用户间的文件共享。**可以用不同的文件名指向同一个文件**，甚至可以指向同一个目录（共享同一目录下的所有内容，eg硬链接）。

软硬链接是文件系统级的引用机制，内核直接识别并共享文件或目录；快捷方式只是用户界面的路径指针，内核层并不识别它。
![](有向无环边.png)
***共享实现***：文件系统为每个文件维护一个**共享计数器**，记录有多少目录项或进程正在引用它。创建硬链接或打开文件时计数器加一，删除目录项或关闭文件时计数器减一。当计数器变为 0，说明没有任何引用，系统才回收文件的数据块。这样即使所有硬链接被删除，只要文件还被打开或引用，数据仍保留，避免误删，也保证多用户共享时的安全性。
通过**硬链接**，你可以在不同目录下创建不同名字的目录项，它们都指向同一个文件的 inode。
不一定是每个文件，但通常是**每个可被共享或需要跟踪使用状态的对象**。
文件共享时写操作顺序进行，修改不会自动反映到其他用户进程，如果希望实现文件修改的**实时渲染**或**同步更新**，就需要在每次提交修改后，向所有正在访问该文件的用户进程发送更新通知，让它们重新读取最新内容。这种机制类似于**订阅-通知模型**，文件系统本身不会主动刷新各进程内存中的缓存，必须通过通知或重新读取来保证一致性。

因为查找文件时**仅需关心用户名**，所以可以将目录表分成**多级索引表**，表中**仅含两个字段**<文件名，索引节点指针>。这样可以**大幅增加检索速度**，同时**降低读入内存的文件大小**。

存放在外存中的索引节点称为“**磁盘索引节点**”，当索引节点放入内存后称为“**内存索引节点**”。相比之下**内存索引节点中需要增加一些额外信息**，例如：文件是否被修改、此时有几个进程正在访问该文件

## 文件存储空间管理
### 存储空间的划分与初始化
安装 **Windows 系统** 时，分区是必要步骤。分区是将物理磁盘划分为 **文件卷**（也称逻辑卷、逻辑盘）。
每个分区中都包含 **目录区** 和 **文件区**：
- **目录区**：用于存放 **文件目录信息**（如文件控制块 FCB）和 **磁盘存储空间管理信息**。
- **文件区**：用于存放 **文件数据**。
在支持超大型文件的系统中，一个文件卷可以由 **多个物理磁盘组成**，以便支持单个文件跨磁盘存储。
存储空间初始化时，需要将每个 **文件卷** 划分为 **目录区** 和 **文件区**，并建立相应的管理结构，以保证文件系统能够正常运行。
#### 文件卷（逻辑卷）的概念
- 文件卷是操作系统管理的 **逻辑存储单位**。
- 可由单个或多个物理磁盘组成，支持大文件存储。
    
#### 文件区与目录区
- **目录区**：存放文件元数据和空间管理信息，包括 **文件控制块（FCB）**。
- **文件区**：存放文件实际内容数据。
### 存储空间管理
#### 空闲表法
记录空闲块的起始地址和空闲盘块长度。适用于物理结构为连续分配方式的系统。
连续分配空间同样可采用首次适应、最佳适应、最坏适应等算法决定为文件分配哪个区间。
要注意合并的问题
#### 空闲链表法
**空闲盘块链**：以**盘块**为单位组成一条空闲链，空闲盘块中**存储着指向下一个空闲盘块**的指针。
**空闲盘区链**：以**盘区**为单位组成一条空闲链，**连续的空闲盘块是空闲盘区**，空闲盘区中的**第一个盘块**中记录了盘区长度和下一个盘区的指针。

盘块链：**链头和链尾的指针由系统保存**，每次从**链头**开始摘取磁盘块进行分配。回收的块依次挂到**链尾**。适用于离散分配的物理结构，分配多个盘块时可能需要多次重复操作。

盘区链：**链头和链尾的指针由系统保存**，若文件申请k个盘块，通过算法后找到一个大小符合要求的空闲盘区分配。若**无连续空闲块**，**也可以**将**不同盘区**的盘块进行分配。若回收区与空闲盘相邻，则需要将回收区合并到空闲盘中。若回收区没有和任何空闲区相邻，回收区作为单独的空闲区挂到链尾。

#### 位示图法
用二进制位表示盘块状态，在平面空间中每个二进制位对应一个盘块。0代表空闲，1代表占用。位示图一般用连续的“字”来表示，也可以用字号、位号描述一个盘块。有的题目中会称作行列号。
要注意题目中盘块号、字号、位号是从0还是1开始。

#### 成组链接法
空闲链表法不适合大型系统，因为空闲表或空闲链表可能过大。UNIX系统中采用了**成组链接法**对磁盘空闲块进行管理。
**文件卷的目录区中**专门用一个磁盘块作为“超级块”，当系统启动时需要**将超级块读入内存**。而且要保护内外存超级块的**数据一致性**。

超级块中通常保存：
1️⃣ 当前组中空闲块的数量 n 
2️⃣ 一个数组 free[n] —— 存放 n 个空闲块号
注意：
- 它**不是**“下一组起始地址”
- 它是**下一组的所有块号集合**

组中记录的是下一组空闲盘块数量，和这些空闲盘块号的集合。如果已经没有下一组空闲块，则可设置一个特殊值在本组第一个盘块号位用于表示。
超级块中的 count表示：
> count 始终表示“当前加载到超级块中的那一组”的空闲块数量。

成组链接法本质上是：从当前组的数组中“弹出一个块号”
至于是：
- 从数组尾部弹出
- 还是从数组头部弹出
完全取决于实现方式。

开始进行分配时，会检查当前分组的空闲块数是否满足所需的空闲盘块数。当前组最后一个空闲块存储了下一组的起始块号。当这块也被分配后，分配器更新指向下一组的起始块号，从而继续分配下一组的空闲块，看起来就像“从当前组重新开始”，但实际上是切换到了下一组。

最后一个块先提供“下一组空闲块集合”给缓存/寄存器，当前块被分配后，超级块控制信息才引用这个集合，确保分配顺序正确且不丢失下一组信息。

![](成组链接法.png)

***回收***时，如果可以插入未满的空闲块组，则加入。如果没有插入的条件，则令当前回收的块成为第一个分组。超级块中**永远指向的是第一个分组**，所以此时也要同步更新超级块中的控制信息。

## 文件的基本操作
创建、删除、读、写、打开、关闭文件分别对应着create, delete, read, write, open, close系统调用

进行create系统调用时，需要提供的主要参数：**所需外存大小**，**路径**，**文件名**。其中获取**所需外存大小**和修改创建该文件所对应的路径的**目录项**是操作系统**自动处理**的。

进行delete系统调用时，主要参数为：**文件存放路径**，**文件名**。其中找到文件名对应的目录项，回收文件占用的磁盘块，删除其对应的目录项由操作系统自动处理。

进行open系统调用时。主要参数为：**文件存放路径**，**文件名**，**需要对文件进行的操作类型**(rw, r, w)。**其中找到文件名对应的目录项**，检查用户是否有权限操作、将目录项复制到内存中的**打开文件表**中，将对应表目返回给用户，之后用户使用打开文件的编号指明要操作的文件，由操作系统自动处理。
打开文件表：用户的打开文件后，相关信息就被读入了内存。用户之后想要操作就不需要重新访问目录了，可以加快文件访问速度。每个用户进程和系统(**唯一**)的打开文件表是分开的。进程的打开文件表字段中会有**读写指针**（记录当前指针位置）、**读写权限**（记录进程对文件的访问权限）、**系统表索引号**，当打开同一个文件时，系统的打开文件表中的字段**打开计数器**则会+1，此时如果单方想要进行delete系统调用则会被提示文件被占用。

进行close系统调用时，会将该进程对应的打开文件表**相应表项删除**，**回收**分配给该文件的内存空间等资源，系统的打开文件表的**打开计数器-1**，如果为0则会删除对应表项

进行read系统调用时，需指明要读的文件**在打开文件表中的索引号**，**读入多少数据**，读入的**数据存放在内存中的什么位置**。操作系统会从读指针指向的外存中，将用户指定大小的数据读入用户指定的内存区域中。

进行write系统调用时，需要指明其在**打开文件表中的索引号**，要**写出多少数据**，写回外存的**数据在内存中的什么位置**。

进行open系统调用时，并没有将文件读入内存，而是读入了文件所对应的目录项的信息到内存中的打开文件表中，并将打开文件表的**索引号**（也称作***文件描述符***）返回给用户。

## 文件共享
由操作系统提供文件共享服务。
多个用户共享同一个文件意味着仅有“一份”文件数据，只要某个用户更改了文件数据，其他用户也可以看见文件数据的变化。
### 基于索引节点的共享方式（硬链接）
索引节点是一种文件目录的瘦身策略。由于检索文件时仅需用到文件名，因此可以将除了文件名之外的信息放到索引节点中。这样目录项仅需要包含文件名、索引节点指针。
索引节点中还会设置一个计数变量count，用于表示**链接到本索引节点上的用户目录项数**。当count=0时，这个文件就会**无法被正常访问**，其所占用的数据块会被标记为free, 等待被覆写/释放空间。

### 基于符号链的共享方式（软连接）
类似win的快捷方式
打开时操作系统会判断其文件类型，当识别到为link类型时，会根据其中的路径信息检索目录最终找到指向的文件。
软连接指向的文件被删除时不会立即删除软连接，而是报错找不到对应目录项。
由于用软连接的方式访问共享文件时**需要查询多级目录**，**所以会有多次I/O操作**

## 文件保护
Windows中的访问控制可在属性中的安全选项卡进行设置，对其他用户可使用guest游客账户
### 口令保护
为文件设置一个“**口令**”，用户请求访问该文件时必须提供口令。
口令一般存放在文件对应的**文件控制块FCB或者索引节点**中。用户访问前需要先输入口令，**操作系统负责核验**。
优点：空间开销小，时间开销也小
缺点：正确的口令放在系统内部，不够安全

### 加密保护
根据某种密钥对文件进行**加密**，在访问文件时需要提供正确的密钥进行**解密**。
- **密钥**：用于加密和解密数据的字符串，确保数据在存储和传输过程中的安全性。密钥可以是对称密钥（同一密钥用于加密和解密）或非对称密钥（公钥和私钥配对使用）。
- **凭据**：用于身份验证和授权的敏感信息，如用户名和密码、API密钥、令牌等。凭据通常用于访问受保护的资源和服务。

优点：保密性强，不需要存储密钥
缺点：加密/解密(编码/译码)需要一定时间开销

### 访问控制
在FCB或索引节点中增加一个访问控制列表(ACL,  Access Control Lists)，该表中记录了各个用户对该文件执行哪些操作。
精简的访问列表：以**组**为单位，标记各组用户可以对文件执行哪些操作

## 虚拟文件系统
计算机内部可能会存在有不同的文件系统，同时外部设备所使用的文件系统可能也会和计算机不同。对于每个文件系统的函数调用**规范可能不同**，跨文件系统操作会极其麻烦，所以引入了**虚拟文件系统**（VFS）。
***依旧是增添中间件***，向上层用户进程提供了**统一标准**的调用接口，屏蔽了底层具体文件系统的实现差异。
**虚拟文件系统**要求了下层的文件系统**必须实现**某些规定的函数功能，例如open/read
/write。它定义统一接口并在运行时通过函数指针调度下层文件系统实现；下层文件系统**必须**在注册时**提供符合接口规范的操作函数**。
*虚拟文件系统既不会自动解析用户请求后自行完成操作，也不会随意调用下层函数；它依赖下层文件系统按照规定接口注册操作函数，然后在统一抽象层中进行调度分发。*
VFS 定义接口规范  
文件系统实现接口  
VFS 在运行时通过函数指针动态分派
当系统调用进入内核后，VFS 会根据 inode 中保存的**操作函数指针表**，进行一次函数指针**跳转**，从而**调用具体文件系统的实现代码**。这是一种基于结构体函数指针的运行时分派机制，而不是别名替换或名称查找。
在传统 VFS 模型中，**vnode 持有操作函数表**并**指向 inode**；在 Linux 中，inode 同时承担 vnode 角色，**操作函数表直接存放在 inode 结构体内**。

打开文件后，具体的文件信息会被制作成为vnode(v结点)，统一了其信息记录标准（目录项）。vnode只会存在于主存中，inode既会调入主存，也会存储于外存。

## 文件系统挂载
即文件系统安装/装载
1. 在VFS中注册新挂载的文件系统。内存中的**挂载表**(mount table)包含文件系统相关信息，例如系统类型和容量大小
2. 新挂载的文件系统要向VFS提供一个**函数地址列表**（用于实现不同文件系统间的系统调用）
3. 将新文件系统加到挂载点(mount point),也就是将新文件系统挂载到某个父目录下（win下挂载点通常是一个**目录或逻辑盘**。，和其他逻辑盘平级；mac为根下的volume目录下）

#  I/O设备
可以将数据输入到计算机或者可以接收计算机输出数据的外部设备，属于计算机中的硬件部件
UNIX系统将外部设备抽象为一种特殊的文件，用户可以使用与文件操作相同的方式对外部设备进行操作。

I/O设备按**使用特性**可以分为：**人机交互型外部设备**（鼠标键盘）、**存储设备**(U)、**网络通信设备**( 光猫)
I/O设备按**传输速率**可以分为：**低速设备**(键鼠)、**中速设备**(打印机)、**高速设备**(硬盘)
I/O设备按**信息交换的单位**可以分为：**块设备**、**字符设备**

## I/O控制器
I/O设备的**机械部件**主要用来执行具体的I/O操作。**电子部件**通常是一块插入主板扩充槽的印刷电路板。
这个**电子部件**就是I/O控制器，又称**设备控制器**，CPU可控制I/O控制器，又由I/O控制器来控制设备的机械部件。

I/O控制器的功能：**接受和识别CPU发出的命令**、**向CPU报告设备的状态**、**数据交换**、**地址识别**
- CPU发起的调用，在I/O控制器中会有相应的**控制寄存器**来存放命令和参数。
- I/O控制器中会有相应的**状态寄存器**用于记录I/O设备的当前状态。如：1表示空闲，0表示忙碌
- I/O 控制器包含**数据寄存器**用于在 CPU 与外设之间缓冲数据。输出时，CPU 将数据写入数据寄存器，控制器在设备就绪后按照设备协议将数据发送给外设；输入时，控制器将外设提供的数据写入**数据寄存器**，CPU 再从该寄存器读取数据。
- 类似于内存的地址，为了**区分**设备控制器中的各个寄存器，也需要给各个寄存器设置一个特定的**地址**。I/O控制器**通过CPU提供的地址来判断**CPU要读/写的是哪个寄存器

一般可分为三个部分：CPU与控制器的接口、I/O逻辑模块、控制器与I/O设备的接口
I/O逻辑负责接收和识别CPU的各种命令，并对设备发出指令。
CPU通过**地址线**和**控制线**对I/O逻辑模块发送指令和地址，同时通过数据总线将需要输出的数据和指令参数放入**数据寄存器**和**控制寄存器**中。状态寄存器通过数据总线反馈各设备的状态给CPU。
一个I/O控制器可能对应多个设备、各寄存器可能有多个，每个寄存器对应一个具体设备，且都有相应的地址。有的计算机会令寄存器占用内存地址一部分，称为**内存映像I/O**；另一些采用专用地址，即**寄存器独立编址**

内存映射I/O采取的是统一编址，可以采用对内存进行操作的指令对控制器进行操作；独立编制需要专门的指令来实现对控制器的操作，不仅要指明寄存器的地址，还要指明控制器的编号。

## I/O控制方式
需要注意：
1. 完成一次读/写操作的流程
2. CPU干预的频率
3. 数据传输的单位
4. 数据的流向
5. 优缺点
![IO控制方式对比](IO控制方式.png)
### 程序直接控制
CPU通过控制线发送读指令，设备启动，状态寄存器设置为1（忙碌）
因为设备需要时间完成命令，所以CPU会不停**轮询**检查控制器状态，直到状态寄存器中的状态字回到0。CPU在这之后从数据寄存器中取出数据，再将数据从CPU寄存器中写入存储器。
I/O开始前和完成后都需要CPU介入，且过程中不断轮询，所以**CPU介入很频繁**
**每次读写一个字**
读：I/O设备 -> CPU -> 内存
写：I/O设备 <- CPU <- 内存
优点：实现简单，读写指令之后加上循环检查的指令即可
缺点：CPU和I/O设备只能串行工作，CPU需要轮询，长期处于“忙等”状态，利用率低

### 中断驱动方式
引入了中断机制，在CPU发出读写命令后，可将等待I/O设备的进程**阻塞**。当I/O完成后，控制器会向CPU发出一个**中断信号**，CPU**检测到中断信号后**，会保存当前进程的运行环境信息，转去执行中断处理程序处理中断。处理时从I/O控制器读一个字数据传输到CPU寄存器，再写入主存。接着，CPU**恢复等待I/O的进程（或其他进程）的运行环境，然后继续执行**.
- CPU在每个指令周期末尾检查**中断**
- 中断过程需要时间开销，不宜太频繁
- 仅开始之前和完成之后需要CPU介入，**干预频率低**
- 每次读写一个字
读：I/O设备 -> CPU -> 内存
写：I/O设备 <- CPU <- 内存

优点：解决了程序直接控制中的CPU忙等，CPU利用率明显提升。可并行工作
缺点：每次只能传输一个字，传输大量字时会消耗大量CPU时间（大量中断）

### DMA方式
与“中断驱动方式”相比，**DMA方式**（Direct Memory Access, 又称**直接存储器存取**，主要用于块设备的I/O控制）的改进为：
1. 传输单位是“**块**”
2. 数据流向**跳过了CPU**，直接是I/O设备和内存的交互
3. 仅传送一个或多个数据块时，才需要CPU干预

CPU负责告诉I/O模块需要进行的操作和参数（地址，读写数据大小），在任务完成之后向CPU发出一个中断信号，通知CPU处理

***`DMA控制器`*** 和I/O控制器长的差不多：
1. DR(Data Register, 数据寄存器)：暂存内存和设备通信的数据
2. MAR(Memory Address Register, 内存地址寄存器)：在输入时，MAR表示数据存放在内存中的位置，输出时表示输出的数据存放在内存中的什么位置；**数据输入到哪里/要输出的数据在哪里**
3. DC(Data Counter, 数据计数器)：表示剩余要读/写的字节数
4. CR(Command Register, 命令/状态寄存器)：用于存放CPU发来的I/O命令，或设备的状态信息

在实际传输过程中，也是**按字传输**。通过DR作为字的寄存地址传入内存，最终完成一整块的读写操作。但是对于CPU视角来说，只有传送一个或多个数据块时，才需要通知CPU。
每次读写都需要是***一个/多个连续的块***，如果是**离散**的则需要通知CPU多次
降低了CPU介入频率，提升了并行性，**数据传输效率增加**
缺点：CPU每次发出I/O指令只能读写一个或多个连续块，离散数据需要多次发出指令。

### 通道控制方式
**通道**：一种**硬件**，相当于一个**简化过的CPU**。通道可以识别并执行一系列通道指令。
CPU向通道发出I/O指令，指明通道程序在内存中的位置，并指明要操作的是哪个I/O设备，剩下的交由通道程序处理（队列）。
通道执行内存中的通道指令，其中指明了读写的**数据大小**和**地址信息**。通道完成任务后向CPU发出中断信号，由CPU介入处理。
*CPU 交给通道的是“通道程序（Channel Program）”，通道负责按照该程序控制设备完成数据传输并向 CPU 报告结果。*
通道程序由一系列 **通道命令字（CCW, Channel Command Word）** 组成，**本质是I/O操作的执行脚本**。CPU还会指明**内存缓冲区信息**（数据在内存中的位置、数据长度、数据读写方向）、**设备地址**。通道负责控制设备、完成数据传输、处理异常并在完成后通过中断通知 CPU。

数据传输单位是**一组数据块**
读：I/O设备 -> 内存
写：I/O设备 <- 内存

**通道程序（Channel Program）不是由 CPU 调度执行的计算任务**，而是由通道硬件自行解释并执行的 I/O 控制指令序列。

优点：CPU、通道、I/O设备可并行工作，资源利用率高
缺点：实现复杂，需要专门的通道硬件支持

## I/O软件层次结构
![](I-O层次思想.png)
每一层都屏蔽了下层繁琐的操作向上层提供服务，用户的请求通过一系列转义对硬件进行操作，属于封装思想。
- 用户层实现了**用户交互的接口**，可直接使用该层提供的**库函数**(Windows API)对设备操作
- 设备独立性软件层又称**系统调用处理层**，向上层提供了系统调用的接口。将用户请求翻译成格式化的I/O请求，通过系统调用请求操作系统内核的服务。**设备独立性软件**又称为**设备无关性软件**，与设备硬件特性无关的功能都在该层实现。设备被看做特殊的文件，对各个用户的访问权限不一样。实现：**调用**、**安全性**、**差错处理**、**设备的分配与回收**、**数据缓冲区管理**、**逻辑设备名到物理设备名的映射关系，并根据类型调用相应的驱动程序**。
- **设备驱动程序层**主要负责对硬件设备的具体控制，将上层的命令转译为设备能“理解”的指令。驱动程序一般作为独立进程存在。
- **中断处理程序层**负责在任务完成、异常时发送一个中断信号，系统会根据中断信号类型执行相应的中断处理程序。硬件会**直接和中断处理程序进行交互**。

缓冲技术可以屏蔽设备之间数据交换单位大小和传输速度的差异
**设备独立性软件**需要通过“**逻辑设备表(LUT, Logical Unit Table**)”来确定逻辑设备对应的**物理设备**，并找到该设备对应的**设备驱动程序**（驱动程序入口地址），可以整个系统共享一张表或每个用户都设置一张表，分别：各个用户不能使用相同的逻辑设备名、可以使用相同的逻辑设备名。
**设备驱动程序**用来消除设备之间的差异，作为中间件将数据格式化后反馈给操作系统。例如设置设备寄存器，检查设备状态等。
*在操作系统中，只有 **设备驱动程序（包含其中的中断处理程序）** 会与硬件寄存器和设备直接交互，其他应用程序通常通过系统调用访问驱动接口，从而间接控制硬件。*

### 输入/输出应用接口 & 设备驱动程序接口
**用户层**应用程序**无法**用一个**统一的**系统调用**接口**完成**所有类型设备**的I/O操作
例如键盘、打印机，**不可”寻址“，每次仅读一个字符**；**硬盘可”寻址“，每次读写一个块**；网络控制器**数据交付给谁？**
字符设备接口、块设备接口、网络设备接口（网络套接字接口）所使用的语法和语义是不一样的。

所以设备独立性软件层将物理上不同的设备按类别进行**逻辑分组管理**，并提供**统一的 I/O 接口**。当用户发出 I/O 请求后，该层查找**逻辑设备表**找到对应的设备驱动程序，再由驱动程序**将请求转化为特定设备可执行的指令**，实现对设备的操作。在此过程中，设备独立性软件层负责**逻辑类别区分**，而驱动程序层负责**屏蔽设备间的具体差异**，使系统能够**以统一方式操作不同硬件**。

**阻塞I/O**：应用程序发出I/O系统调用，**进程需转为阻塞态等待**。例如字符设备接口，键盘读取字符 get。CPU 等待设备输入，因为用户输入速度极慢，不需要并行处理，键盘采取中断驱动方式。
**非阻塞I/O**：应用程序发出I/O系统调用，系统调用可迅速返回，**进程无需阻塞等待**。例如块设备接口，往硬盘写数据 write。CPU 不阻塞，因为数据已缓存在内存，磁盘控制器、DMA 或通道可在后台完成数据传输。

设备驱动程序接口可以参考VFS（虚拟文件系统），由系统规定好设备驱动程序的接口标准，各厂商必须按要求开发设备驱动程序。
如果设备驱动程序接口不符合操作系统规范，操作系统通常会 **拒绝加载/注册驱动**，设备无法提供服务，并向用户或日志提示设备存在，但不会允许任何不规范的直接交互。

### I/O核心子系统
中三层属于操作系统**内核部分**，即**I/O系统**，或称为**I/O核心子系统**（设备独立性软件层、设备驱动程序层、中断处理程序层）
假脱机技术(SPOOLing技术)在用户层软件实现
设备独立性软件层实现：**I/O调度**、**设备保护**、设备分配与回收、缓冲区管理

I/O调度：**用某种算法确定一个“好”的顺序来处理各个I/O请求**。例如磁盘调度
**设备保护**：设备被看做一种特殊的文件，每个设备有对应的FCB，系统根据此判断用户是否有相应的访问权限。

## 假脱机技术
用**软件**的方式实现了脱机。**脱机技术**：脱离主机的输入/输出操作。
由于手工操作阶段，主机直接从I/O设备获取数据，设备速度慢，人机速度矛盾明显，主机需要浪费很多时间等待设备完成，所以引入了脱机输入/输出（用磁带完成）
在**外围控制机**的控制下，慢速输入设备的数据先被输入到快速的磁带上，之后主机快速的从磁带上读入数据，从而缓解了速度矛盾。
即使CPU在忙碌，也可以提前将数据输入到磁带；即使设备在忙碌，也可以提前将数据输出到磁带。“提前”指的是 **CPU或通道提前准备数据缓冲**，**CPU或通道提前把数据放到缓冲区，设备处理在后台完成**，用户输入只是数据源。

**SPOOLing技术**用软件的方式模拟脱机技术，在硬盘上开辟了两个存储区域“**输入井**”和“**输出井**”，用于收容用户进程读写操作的数据。**外围控制机**由其他进程**模拟**。
**必须有多道程序技术的支持**，在进程控制下，会先将I/O操作的数据放入内存中的缓冲区，再慢慢进行后续操作。
通过将物理设备**虚拟**成逻辑上的多台设备，**可将独占式设备改造成共享设备**。

## 打印机共享原理分析
**独占式设备**，仅允许串行，一段时间内仅有一个进程可访问。
**共享设备**，允许多个进程“**同时**”使用，宏观上同时，微观上**交替**。
**SPOOLing技术**作为**中间件**缓存了用户发送的作业请求

## 设备的分配与回收
### 应当考虑的因素
**设备的固有属性**、**设备分配算法**、**设备分配中的安全性**
设备的固有属性分为：独占属性、共享设备、虚拟设备
设备的分配算法：先来先服务、优先级高者优先、短任务优先等
从进程运行的安全性上考虑，设备分配有两种方式：
**安全分配方式**：为进程分配一个设备后将进程阻塞，在I/O操作完成后再唤醒；只能**串行**，不会死锁
**不安全分配**：进程发出I/O请求后，系统为其分配I/O设备，进程可继续执行，之后还可发出新的I/O请求。只有某个I/O请求得不到满足后才进行阻塞。可以**并行**，可能死锁

### 静态分配与动态分配
静态分配：一次性提前分配完所有需要的资源，运行结束后归还。不会死锁
动态分配：动态的申请所需资源，可能死锁

### 设备分配管理中的数据结构
类型、标识符、状态、指向另一张表的指针、等待队列，不包含系统控制表
**设备控制表DCT**：系统为每个设备配置一张DCT，用于记录设备情况
- 设备类型  
- 设备标识符  设备名
- 设备状态  忙碌/空闲/故障
- 指向控制器表的指针   每个设备由一个控制器控制，用于找到对应的控制器
- 重复执行次数或时间   重复多次I/O操作后仍不成功则认为失败
- 设备队列的队首指针   指向正在等待该设备的进程队列（由进程PCB组成队列）

**控制器控制表COCT**：每一个设备控制器都会对应一张COCT。操作系统根据COCT的信息对控制器进行操作和管理。
- 控制器标识符
- 控制器状态
- 指向通道表的指针   每个控制器由一个通道控制，该指针用于查找相应的通道
- 控制器队列的队首指针   指向正在等待该控制器的进程队列（由进程PCB组成队列）
- 控制器队列的队尾指针   指向正在等待该控制器的进程队列（由进程PCB组成队列）

**通道控制表CHCT**：每个通道都会对应一张CHCT。操作系统根据CHCT的信息对通道进行操作和管理。
- 通道标识符
- 通道状态
- 与通道连接的控制器表首址  通过该指针找到通道管理的所有控制器相关信息（COCT）
- 通道队列的队首指针   指向正在等待该通道的进程队列（由进程PCB组成队列）
- 通道队列的队尾指针   指向正在等待该通道的进程队列（由进程PCB组成队列）

类型、标识符、设备控制表、驱动程序入口
**系统设备表（SDT）**：记录了**系统中全部设备**的情况，每个设备对应一个条目。
- 设备类型
- 设备标识符
- 设备控制表DCT
- 驱动程序入口

### 设备分配步骤
- 根据请求的物理设备名查找**系统设备表SDT**，从中查询**设备控制表DCT**，DCT中含有指向**控制器控制表COCT**的指针，COCT中又有指向**通道控制表CHCT**的指针.
- 除开第一次访问系统设备表SDT，其余每一次都需要先查看**状态**。当设备、控制器、通道三者都成功分配时，设备分配才算成功，之后可启动I/O设备进行数据传输。

缺点：用户编程时必须使用物理设备名，底层细节不透明不方便编程；若换了一个物理设备则程序无法运行；若进程请求的物理设备正在忙碌，即使系统中还有同类型的设备，进程也需要阻塞等待。

改进方法：建立逻辑设备名和物理设备名的映射，用户编程时使用逻辑设备名。操作系统会建立**逻辑设备表LUT**记录逻辑设备名、物理设备名、驱动程序入口地址
1. 根据进程请求的**逻辑设备名**查找系统设备表SDT
2. 查找SDT，找到用户进程**指定类型的且空闲**的设备，分配给进程。操作系统在逻辑设备表LUT中新增一个表项
3. 根据DCT找到控制器控制表COCT
4. 根据控制器控制表COCT查找通道控制表CHCT

依旧是两种设置方式：整个系统共用一张逻辑控制表LUT和每个用户一张逻辑控制表LUT

## 缓冲区
作为一个存储区域，可以由专门的硬件寄存器组成，也可利用内存作为缓冲区。
使用**硬件**作为缓冲区的**成本较高**，容量也较小，一般仅用在对速度要求非常高的场合，如存储器管理中所用的联想寄存器，由于对页表访问频率极高，因此使用速度很快的联想寄存器来存放页表项的副本。
***一般都使用内存作为缓冲区***，设备独立性软件的缓冲区管理就是要组织管理好这些缓冲区。

CPU可以将要输出的数据存入缓冲区，慢速的I/O设备会从缓冲区取走数据，防止长时占用CPU，缓解了CPU和I/O设备的速度差。
字符型设备每输出完一个字符就要向CPU发送一次中断信号。

### 单缓冲
假设某用户请求某种块设备读入若干块的数据。若采用**单缓冲**的策略，操作系统会在主存中为其分配一个缓冲区。
缓冲区数据**非空**时**不可冲入数据**；缓冲区为空时可以冲入数据，但只有在**充满后才可取出数据**。

### 双缓冲
假设某用户进程请求某种块设备读入若干块的数据。若采用**双缓冲**的策略，操作系统会**在主存中为其分配两个缓冲区**。
双缓冲区适合双通道通信，可以实现双向的数据传输。

### 循环缓冲区
将多个**大小相等**的缓冲区**链**接成一个**循环队列**
使用一个指针表示下一个可以冲入数据的空区，另一个指针指向下一个可以取出数据的满区

### 缓冲池
由系统中共用的缓冲区组成。按使用状况分为：**空队列**、装满输入数据的缓冲队列（**输入队列**）、装满输出数据的缓冲队列（**输出队列**）
根据缓冲区在实际运算中扮演的功能不同，又设置了四种工作缓冲区：用于收容输入数据的工作缓冲区（**hin**）、用于提取输入数据的工作缓冲区（**sin**）、用于收容输出数据的工作缓冲区（**hout**）、用于提取输出数据的工作缓冲区（**sout**）
*s/h对应的是硬件和软件？但还是建议理解为Serve和Hold，分别代表提供/存放设备输入/输出*
1. 输入进程请求输入数据时，会请求一块空缓冲区用于hin收容输入数据
2. 在hin满后会挂至输入队列的队尾，用于sin提取输入数据
3. 计算进程将准备好的数据冲入缓冲区hout，然后挂载至输出队列队尾
4. 从输出队列中取下一块缓冲区用于sout，取走数据

# 磁盘
磁盘表面由一些磁性物质组成，可以用这些磁性物质来记录**二进制**数据。
磁盘内部包含：空气过滤片、**主轴**（马达电机和承轴在其下方）、音圈马达、**永磁铁**、**磁盘**、**磁头**、磁头臂

磁盘的扇面被划分为**磁道**，结构上为同心圆。每个磁道又被划分为**容量相等**的**扇区**。最内侧的扇区面积最小，数据密度最大。
读写数据时需由磁头臂带动刺头移动至想要读取的扇区，当目标扇区从磁头下方**划过**时即视作完成对扇区的读写操作。
磁盘内部有多个**盘片**，每个**盘片**都有其读取磁头，一个盘片可能有两个盘面（正反面）。**所有磁头连接在同一个磁头臂**上，所有盘面中相对位置相同的磁道组成柱面。可用<**柱面号**、**盘面号**、**扇区号**>来定位任意一个“磁盘块”，也可认为是文件数据存放在外存中的几号块。
- 移动磁臂指向制定柱面->激活制定盘面的刺头->磁盘旋转过程中，扇区从刺头下划过，就完成了读写。

磁头可移动的称为**活动头磁盘**，**磁臂**可以**来回伸缩**来带动刺头定位磁道；磁头不可移动的称为**固定头磁盘**。这种磁盘中每个磁道有一个磁头。
盘片可更换的成为**可换盘磁盘**，不可更换的为**固定盘磁盘**。

## 磁盘调度算法
磁盘读写操作需要的时间开销为：寻道时间+延迟时间+传输时间
**寻道（找）时间**：在读写数据前，移动磁头到指定磁道所花的时间为s。**启动磁头臂**和**移动磁头**都需要时间。假设磁头匀速移动，每跨越一条磁道耗时为m，需要跨越n条磁道，则寻道时间=s+mn

延迟时间：通过旋转磁盘，使磁头定位到目标扇区所需要的时间。设磁盘转速为r，则平均所需延迟时间为$\frac{1}{2}*\frac{1}{r}=\frac{1}{2r}$ 找到目标扇区**平均需要转半圈**。单位是转/秒或分

传输时间：从磁盘读出或写入数据需要经历的时间，假设转速为r，此次读写的的字节数为b，每个磁道上的字节数为N，则传输时间=$\frac{1}{r}*\frac{b}{N}=\frac{b}{rN}$ 每个磁道存储N字节数据，所以b个字节的数据需要$\frac{b}{N}$ 个磁道存储，读写一个磁道的时间又是转一圈所需时间$\frac{1}{r}$ 

延迟时间和传输时间**由磁盘决定**，**寻道时间**由操作系统的**磁盘调度算法决定**.

### 先来先服务(FCFS)
老朋友了，以队列思想理解即可，每次取队头。
要注意磁道移动距离，例如初始为53，队中为3、150、30，总共移动的距离为50+147+120=317个磁道，相应一个请求平均需要移动105.7个磁道
公平，但是如果请求访问的磁道**较为离散**，则**寻道时间会很长**，时间开销大

### 最短寻找时间优先(SSTF)
SSTF优先处理离当前磁头**最近的磁道**。可以保证每次寻道时间最短，但是不能保证总体时间最短。（贪心算法思想）
**性能好**，**平均**寻道**时间短**，可能导致**饥饿**。

### 扫描算法(SCAN)
为了防止最短寻找时间优先SSTF始终在一小块区域内移动而产生饥饿现象，可以规定磁头只能在移动到最外侧磁道时才能向内移动，移动到最内侧时才可向外移动。又称**电梯算法**。
可以认为磁头不会为了具体的请求而停留，而是从小到大，从大到小来回扫描，只需要两轮就一定能扫描完整个盘片（假设磁头不在边缘）

**性能较好**，**平均**寻道时间**短**，**不会饥饿**。
只有到达最边上才能改变磁头移动方向，因此会产生**多余的寻道时间**，例如要访问的最大磁道为180，在访问后仍然会继续移动到200再返回。对于各个位置磁道的**响应频率不平均**，中间匀时，两边是长时和短时交替相应。

### LOOK调度算法
在扫描算法SCAN上优化而来，如果磁头**移动方向上没有别的请求，即可立即改变磁头移动方向**。

### 循环扫描算法(C-SCAN)
为了**解决响应频率不平均**的问题，规定只有磁头朝某个特定方向移动时才处理磁道访问请求，而返回时快速移动至起始端**不处理任何请求**。
更接近循环遍历，轮流一遍以后从0开始
虽然响应频率平均了，但是**平均寻道时间更长**，而且没有解决**多余寻道时间**的问题。

### C-LOOK算法
结合了循环扫描和LOOK算法的思想，即解决了响应频率不平均，又解决了多余的寻道时间，如果磁头**移动方向上没有别的请求，即可立即改变磁头移动方向**。

***算法进步就是一个巨大的套娃***

## 减少延迟时间的方法
移动柱面需要的时间开销最大，需要先启动磁头臂，再激活磁头。
如果柱面号/磁道号相同，仅盘面不同，则仅需激活磁头即可。所以柱面号需要在盘面号之前，重点是减少读取连续地址的时间。
移动柱面所产生的寻道时间开销最大，因为需要驱动磁头臂进行机械移动；在柱面号相同而盘面不同的情况下，仅需切换磁头即可完成访问，延迟极小。因此磁盘地址的组织**应优先保证柱面号连续**，以减少磁头臂移动次数并提升顺序访问性能；若优先按盘面号而非柱面号访问，则可能导致**柱面频繁切换**，**使逻辑连续的数据在物理上呈跳跃分布**，从而显著**增加寻道时间并降低读取效率**。
### 交替编号
采用**交替编号**的策略，让逻辑上相邻的扇区**在物理上有一定间隔**，可以使读取连续的逻辑扇区所需要的延迟时间更小。
扇区读取完毕后磁头需要一定的**准备时间**，这段时间内**不能处理任何访问请求**，如果在这段后摇结束后刚好衔接上下一个扇区，则可减少读取连续扇区所需要的延迟时间。
*否则一圈只能读连续扇区中的一个区*

### 错位命名
在**相邻磁道或柱面之间**，对扇区编号进行人为偏移排列，使得磁头切换或柱面移动后，下一扇区**恰好**旋转到磁头下方。
为了减少旋转延迟与寻道等待，使连续逻辑块能够在磁盘旋转过程中**无等待地连续读出**。
👉 磁头切换 & 柱面移动需要时间  
👉 磁盘仍在高速旋转  
👉 如果编号不偏移，会错过下一扇区
必须等待整整一圈旋转（严重浪费时间）

错位命名是一种通过对相邻磁道或柱面的扇区编号进行偏移排列的优化策略，其目的是**补偿磁头切换或柱面移动**所消耗的时间，使磁头完成切换时下一扇区恰好旋转到磁头下方，从而避免因错过扇区而等待整圈旋转的延迟；该机制配合柱面优先访问策略，可显著减少旋转等待时间并提升连续读写效率。

## 磁盘管理
### 磁盘初始化
磁盘出厂时仅划分了磁道，需要进行**低格**（低级/物理格式化），将磁盘的各个磁道**划分为扇区**。扇区可分为**头、数据**区域、**尾**。管理扇区所需要的数据结构一般存放于头尾，包括扇区校验码（奇偶校验、CRC循环冗余校验码等）
在**低格之后**将磁盘进行**分区**，每个分区由若干柱面组成。
最后进行**逻辑格式化**，创建文件系统。包括创建文件系统的根目录、初始化存储空间管理所用的数据结构（如位示图、空闲分区表）
### 引导块
计算机开机的初始化工作通过**初始化程序**（**自举程序**）完成，一般存放在**只读存储器ROM**中，并且之后不可再修改。
因为要考虑到后续的更新和修改，所以现在ROM中仅存放小的“**自举装入程序**”，完整的自举程序放在磁盘的启动块（即引导块/启动分区）上，启动块位于磁盘的固定位置。
开机时计算机先运行自举装入程序，找到**引导块**，将**完整**的自举程序**读入内存**完成**初始化**

拥有启动分区的磁盘称为启动磁盘或者系统磁盘(C盘)
### 坏块
为了防止错误的使用到坏块，所以在逻辑格式化时会进行标记，指明哪些扇区是坏扇区，不会再被分配数据。例如在**文件分配表FAT**上表明（此种方式坏块**对操作系统不透明**）
对于复杂的磁盘，磁盘控制器（硬盘内部**硬件**）会维护一个**坏块链表**。在出厂前低格时会对坏块链表进行初始化。会保留一些**备用扇区**用于**替换坏块**。这种方案也称为**扇区备用**，**该种方式**中坏块**对操作系统透明**

# 固态硬盘 SSD

固态硬盘由**闪存芯片（Flash Memory）** 构成，基于**闪存存储技术**，属于**电可擦写只读存储器（EEPROM）** 的一种实现形式。

## 组成

**闪存翻译层（FTL, Flash Translation Layer）**  
负责将操作系统发送的**逻辑块地址（LBA）** 映射到实际的物理页位置。

**存储介质**  
由多个**闪存芯片（Flash Chip）** 组成，每个芯片包含多个**块（Block）**，每个块又由多个**页（Page）** 构成。

系统通过 I/O 总线向 SSD 发送逻辑块号，FTL 将其映射到具体物理位置完成访问。

- 页（Page） → 读写最小单位
- 块（Block） → 擦除最小单位

> 页的作用类似于机械硬盘中的扇区，但二者实现机制不同。

系统对 SSD 的访问流程：

- 读写以**页为单位**
- 请求中指定的是**逻辑块号（LBA）**
- FTL 完成逻辑到物理地址转换

SSD 采用**块擦除机制**：

- 已擦除块中的页可写入一次、读取多次
- 若要修改已有数据页，必须擦除整个块
- 为保留块内有效数据，控制器会：
    1. 将有效页复制到新块
    2. 更新映射关系
    3. 擦除旧块备用

这一过程称为 **垃圾回收（Garbage Collection）**。
SSD 支持真正的随机访问，FTL 可通过电路快速定位数据位置。
⚠️ 性能特性：
- **读取速度快**
- **写入较慢**（涉及擦除与数据迁移）
- 随机访问性能远高于机械硬盘

## 特点
- 读写速度快，随机访问性能高
- 采用电路寻址，无寻道延迟
- 机械硬盘依赖磁头与磁臂运动，存在寻道与旋转延迟

其他特性：
- 安静无噪音
- 抗震耐摔
- 功耗低
- 成本较高

寿命差异：
- SSD 的闪存块擦写次数有限，过度擦除可能形成坏块
- 机械硬盘扇区不会因写入次数增加而磨损失效

## 磨损均衡技术（Wear Leveling）

通过将擦除操作**均匀分布到各个闪存块**，延长 SSD 使用寿命。

### 动态磨损均衡
写入时**优先选择擦除次数较少**的块，**避免局部过度磨损**。

### 静态磨损均衡
控制器会迁移长期不变的数据，使旧块承担**以读为主**的任务，而将**写入操作分配给较新的块**，从而实现整体磨损均衡。

## 生产者-消费者
生产者和消费者共享一个**初始为空大小为n的缓冲区**
缓冲区是临界资源，必须**互斥的访问**，否则可能发生覆写的问题
设置信号量mutex，初值为1
设有两个生产者和一个消费者，则可以认为有两对关系，一对互斥，一对同步。
生产者之间使用互锁的信号量，生产者与消费者之间使用同步的信号量
互斥的P操作一定要放在同步的P操作之后，否则可能发生死锁
V则无所谓

## 多生产者-多消费者
生产者和消费者共享一个**初始为空大小为n的缓冲区**
缓冲区是临界资源，必须**互斥的访问**，否则可能发生覆写的问题
因为核心关系是**每一个时刻只能有一个进程进入缓冲区**，虽然写和读可以同时进行，但微观上还是有先后顺序的，所以他们可以共享一个缓冲区锁。而后再建立对应的同步关系和互斥关系
两对互斥，一对同步

在多处理机（多核）系统中，写和读在“硬件层面”可以同时进行，  
但在“逻辑一致性层面”仍然必须表现为某种先后顺序。
在多处理机系统中，如果读写操作具备原子性并通过同步机制建立了先后关系，那么读操作要么观察到写之前的旧数据，要么观察到写之后的新数据，而不会观察到不一致的中间状态。

## 磁盘寻址顺序
### 一、磁盘的物理结构（理解前提）

机械硬盘（HDD）由以下层级组成：

- **柱面（Cylinder）**：所有盘面上半径相同的磁道集合
    
- **磁道（Track）**：盘面上的同心圆轨道
    
- **盘面（Head/Surface）**：每个盘片的上下表面
    
- **扇区（Sector）**：磁道被划分的数据最小单位
    

👉 同一柱面 = 磁头臂无需移动  
👉 不同盘面 = 只需切换磁头  
👉 不同柱面 = 必须移动磁头臂（机械运动）

---

### 二、一次磁盘访问的时间构成

磁盘访问时间主要包括：

#### 1️⃣ 寻道时间（Seek Time）【最大开销】

磁头臂移动到目标柱面所需时间  
👉 机械运动 → 最耗时

#### 2️⃣ 旋转延迟（Rotational Latency）

等待目标扇区旋转到磁头下方

#### 3️⃣ 传输时间（Transfer Time）

数据实际读写时间

其中：

> **寻道时间 ≫ 旋转延迟 ≫ 传输时间**

因此系统优化重点就是：

✅ 减少柱面切换  
而不是减少磁头切换

---

### 三、为什么柱面号要排在盘面号之前？

当访问连续逻辑块时：

#### 情况 A：柱面号相同，仅盘面不同

✔ 不移动磁头臂  
✔ 仅切换磁头  
✔ 延迟极小

👉 访问非常快

---

#### 情况 B：柱面号不同

✘ 需要移动磁头臂  
✘ 机械寻道开销大

👉 访问明显变慢

---

### 四、如果优先按盘面号而非柱面号排序，会发生什么？

如果读取顺序是：

盘面0 → 盘面1 → 盘面2 → …  
而这些数据分布在不同柱面：

就会出现：

- 磁头臂频繁来回移动
    
- 寻道次数激增
    
- 连续读取性能严重下降
    

也就是说：

👉 逻辑上连续  
👉 物理上跳跃

最终导致访问效率下降。

---

### 五、为什么连续地址要按柱面优先布局？

文件系统或磁盘调度策略通常遵循：

**柱面优先 → 盘面次之 → 扇区最后**

这样可以：

✅ 最大限度减少寻道次数  
✅ 提高顺序读写吞吐量  
✅ 提升整体I/O性能

这也是经典磁盘优化策略的核心思想。
## PCB在调度过程中的存放位置
PCB 本体始终位于**内核空间**，不会随进程的调度、切换或换入换出而被移动。在调度过程中，PCB 只是根据进程状态的变化，被**挂接到不同的内核数据结构**中，实际移动的是指向 PCB 的指针。
- **始终在内核空间**
- 由内核动态分配（通常在创建进程时）
- 用户态程序**永远不可直接访问**

当进程被**挂起（suspend）**并换出到外存时：
- **进程的地址空间（代码段、数据段、栈等）被换出到外存**
- **PCB 不会被换出，仍然保留在内核空间**

此时：
- PCB 的状态被标记为 **挂起就绪态（Ready Suspended）** 或 **挂起阻塞态（Blocked Suspended）**
- PCB 通常被挂接在**挂起队列（suspend queue）**中
- PCB 中会记录该进程在外存中的相关信息（如换出位置、映射信息等）

可以概括为一句话：
> **进程挂起时，换出的是进程的执行实体和数据，而不是 PCB；PCB 始终留在内核，用于描述和管理该进程。**

## 名词
**任务（task）**：偏向 CPU 执行单位，常用于线程 / 轻量级调度语境
**作业（job）**：偏向“一整批需要被系统服务的工作请求”，典型场景就是 **批处理、打印、SPOOL 队列**
**`程序=数据结构+算法`**，**算法**(Algorithm)**是对特定问题求解步骤的一种描述**，是指令的**有限**序列，其中每条指令表示一个或多个操作
**内部碎片：分配了但没用完的空间（在分配单元“里面”）**  ，由于分配单位固定或取整，导致“分给你了，但你用不完”的那部分空间。
**外部碎片：没分配但用不了的空间（在分配单元“之间”）**，内存中存在足够的空闲空间，但由于分散成小块，**无法满足连续分配需求**。
**MMU**（**Memory Management Unit，内存管理单元**）： CPU 内部的硬件模块，负责把虚拟地址转换为物理地址。
**TLB**： 在MMU 内部，是一个高速缓存，用于缓存页表转换的结果，从而缩短页表查询的时间。专门缓存虚拟页号 → 物理页号的映射；把“最近用过的地址翻译结果”记下来
程序：静态存在于硬盘或其他存储介质，只是代码和数据文件，不占用内存，也不执行。可以有多个副本，同一程序可以同时作为多个作业存在。程序是潜在作业的蓝图。
作业：当程序被装入内存、准备运行时，就成为作业。作业**包含程序代码、数据段、堆栈以及作业控制信息**，是操作系统以作业为单位进行内存分配和作业调度的对象。作业还未执行或刚开始执行时，可能没有进入 CPU。
进程：是作业在执行期间的动态实体，包含程序计数器、CPU寄存器、内存空间和作业控制信息（PCB）。进程是操作系统调度的最小单位，一个作业可以生成一个或多个进程（如多线程或子进程）。
**时间局部性**：如果执行了程序中某条指令，那不久后这条指令很可能再次执行；如果访问了某个数据，不久后可能再次访问，**因为程序中存在大量循环**。
**空间局部性**：一旦程序访问了某个存储单元，不久后其附近的存储单元也可能被访问，因为**很多数据在内存中是存放的**
**文件控制块**（FCB）：是操作系统为管理文件而建立的数据结构；目录项是目录文件中的一条记录，用于实现文件名到文件控制信息的映射。在某些简单文件系统中目录项与FCB合并实现，而在UNIX类系统中目录项仅保存文件名和inode号，真正的FCB由inode承担。
**目录项**：可能包含FCB信息，但在现代文件系统中二者**通常是分离的**。

## 作业与任务 细说
作业是用户提交给系统的整体工作单元，通常包含程序、数据和 I/O 请求。任务是作业中的可执行子单元，负责具体操作或处理。作业由作业调度器管理，任务由 CPU 或线程调度器管理。在 SPOOLing 或打印场景中，作业可以是一整个打印文件，任务可以是一页或一次缓冲的数据传输。

| 特性   | 作业         | 任务             |
| ---- | ---------- | -------------- |
| 定义   | 用户提交的整体工作  | 作业中的可执行子单元     |
| 大小   | 较大         | 较小             |
| 调度   | 由作业调度器安排   | 由 CPU 或线程调度器安排 |
| 生命周期 | 从提交到系统直到完成 | 作业执行期间完成       |
| 示例   | 打印整个文件     | 打印一页或一次数据传输    |
| 关系   | 包含任务       | 属于作业           |
