# 基础
## ELF文件概述
![[ELF.png]]
ELF文件头表(ELF header)
	- 记录了ELF文件组织结构

程序头表/段表(Program header table)
	- 告诉系统**如何创建进程**
	- 生成进程的**可执行文件必须拥有此结构**
	- 重定位文件非必须

节头表(Section header table)
	- 记录了ELF文件的**节区信息**
	- 用于**链接的目标文件必须拥有此结构**
	- 其他类型目标文件不一定需要

**段**视图：程序**加载到内存**中成为进程后进行读、写、执行权限划分的视图
**节**视图：ELF文件存放在**磁盘中**进行不同功能区域划分的视图

代码（text）段：**代码和只读数据**
text：编译生成的代码主体
rodata：只读的初始化数据，通常是**常量与常变量**
hash：初始化的**全局变量**和**静态变量**
plt：过程链接表
rel.got：重定位节区

数据（data）段：**可读写数据**
data：可读写初始化的**全局变量**和**静态变量**
got：全局偏移表
got.plt：存储链接库函数的最终地址

## 寄存器
amd64寄存器结构：
- rax: 8Bytes
- eax: 4Bytes
- ax: 2Bytes
- ah/al: 1Byte

RIP：存放当前执行的指令的下一跳地址
RSP：存放当前栈帧的栈顶地址
RBP：存放当前栈帧的栈底地址
RAX：通用寄存器，存放函数返回值

在x86架构中为ESP, EBP和EAX。amd64算是一种超集，可包容x86寄存器。

## 从编译到执行
预处理->编译->汇编->链接->执行
gcc -E -> -S -> -c -> -o

|阶段|做什么|
|---|---|
|预处理（-E）|宏展开、头文件展开、条件编译|
|编译（-S）|语法分析 + 生成IR + **优化**|
|汇编（-c）|转机器码|
|链接|合并目标文件|
file 文件名
LSB小端序，MSB大端序
fork：创建一个新的进程
execve：系统调用，它允许进程用一个全新的程序替换当前运行的程序。这个过程中，旧程序的栈、数据和堆段会被新程序所替换
sys_execve：是 Linux 内核中的一个系统调用，用于执行一个新的程序。它会替换当前进程的程序，使其执行指定的可执行文件。这个过程涉及从用户空间拷贝文件名、参数及环境到内核空间，加载可执行文件，并释放旧进程资源等关键步骤。
ld.so：动态链接程序
`_libc_start_main`：静态和动态都会有的一步
`_init`：初始化步骤
load_elf_binary：使用elf格式加载器，解析elf文件头的同时将数据段和代码段映射到内存中。

Base：基地址
index：索引
scale：度
偏移地址=0+2\*4。Displacement，位移。假设位移为0x10。$0+2*4+0x10=24$ 
偏移：offset

| 名称           | 语境                | 是否固定    | 单位  | 举例                         |
| ------------ | ----------------- | ------- | --- | -------------------------- |
| offset       | 高级语言 / 结构体 / 段寄存器 | 通常固定    | 字节  | `offsetof(struct A, y)`    |
| displacement | 汇编寻址（基址+索引）       | 可以动态或固定 | 字节  | `[ebx + esi*4 + 8]` 中的 `8` |
$Effective Address=Base+(Index×Scale)+Displacement$

- **Base（基址寄存器）**：通常是指向数据块或数组起始位置的寄存器（如 `ebx`、`rbp`）
- **Index（索引寄存器）**：数组或结构体内元素的索引（如 `esi`）
- **Scale（度/乘数）**：元素大小（1、2、4、8）
- **Displacement（常偏移量）**：相对于基址的固定偏移，常数
displacement 可以用来**把基址调整到目标数据段起点**，这样 Base + Index\*Scale 就能方便访问数组/序列任意元素，尤其在结构体或栈帧里间隔了其他内容时非常有用。

在AMD架构中，目的操作数在后；在Intel架构中，目的数在前
MOV的两个操作数不能同时为内存，LEA可以将源操作数的**有效地址**传递给寄存器
AMD架构中立即数4的表示为`$4`

|后缀|全称/意义|位数|示例|
|---|---|---|---|
|`movb`|Move Byte|8 位|`movb al, [ebx]` → 将内存 1 字节复制到 AL|
|`movw`|Move Word|16 位|`movw ax, [bx]` → 内存 2 字节复制到 AX|
|`movl`|Move Long|32 位|`movl eax, [ebx]` → 内存 4 字节复制到 EAX|
|`movq`|Move Quad|64 位|`movq rax, [rbx]` → 内存 8 字节复制到 RAX|

## 栈溢出
由于内存中栈的增长方向是从高地址方向向低地址方向增长，压入栈中的数据有可能会替换ret的地址，所以当函数调用结束时，返回的地址就会变成栈溢出导致的地址。
*向局部变量写入内容是从低地址向高地址写，但是栈增方向是高到低*，所以栈溢出经常发生在局部变量处。

## canary与PIE
一种用于防护栈溢出的保护机制，在函数入口处放置一个值存在栈上，当函数结束时会检查这个值是否和存进去的值一致。

Canary bypass：
格式化字符串绕过canary：
- 通过格式化字符串读取canary的值
Canary爆破（针对有fork函数的程序）：
- fork相当于自我复制，每一次复制的程序内存布局都相同，所以Canary的值也一样。逐位爆破后，如果程序崩溃了则说明不对，程序正常就可以接着跑下一位，直到跑出正确的Canary
Stack smashing（故意触发Canary_ssp leak）
劫持__stack_chk_fail
- 修改got表中__stack_chk_fail函数的地址，在栈溢出后执行该函数，由于该函数地址被修改，所以程序会跳转到我们想要执行的地址

在C语言中printf函数结尾是0x00，如果有办法绕过这个printf的结尾，则可连带后续的数据一同打印，直到Canary结尾的0x00

**PIE**针对代码段、数据段、未初始化全局变量段等固定地址的一个防护技术，如果程序开启了PIE保护，则每次加载程序都会变换加载地址，不能通过ROPgadget等工具解题
对于开了PIE保护的程序仅部分地址位已知，但程序加载地址一般以内存页为单位，所以基地址后三位一定为0，此时即可通过利用栈上已有的地址仅修改最后两个字节（四个数）即可
所以核心思想为partial writing（部分写地址）
